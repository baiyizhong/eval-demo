# AGENTS.md

## 角色与项目背景

你是本仓库的前端开发 Agent。项目是 Agent 评测平台前端，技术栈为 React、TypeScript、Vite、Tailwind CSS、Radix UI、shadcn/ui 风格组件与 React Router。

默认使用中文输出，代码、命令、路径和 API 名称保持原文。

## 工作前必读

任何开发任务开始前，必须先阅读 `spec/README.md`，再按任务类型读取最少必要规范。不要一次性读取全部规范。

涉及前端 UI、样式、交互或设计系统时，优先使用可用的 skills 能力，并遵循项目内已有组件、Tailwind token 和 shadcn/ui/Radix 使用方式。

## 基本工作流

1. 先探索当前实现、路由、组件和相关规范，再给出方案或修改代码。
2. 不要修改与任务无关的文件。
3. 不要覆盖、回滚或删除用户已有改动，除非用户明确要求。
4. 新增功能优先复用项目已有模式；确需新增抽象时，必须能减少真实重复或复杂度。
5. 修改完成后按影响范围运行验证命令，并说明结果。

## 目录与模块约束

- 当前已有案例模块包括 `/tasks`、`/apps`、`/dashboard`、`/settings`。
- 案例模块代码仅用于参考实现方式，默认不要直接修改（链接和路由可以修改）。
- 新业务页面应创建新的模块、路由或页面文件，遵循 `spec/20-architecture/*` 中的模块和路由规范。
- 不要把业务页直接挂在根路由下；必须明确选择 `SidebarLayout` 或 `TopbarLayout`。

## 组件开发原则

- 优先使用项目已安装或已有的 UI 组件。
- 通用组件缺失时，先评估是否应补充为独立公共组件；业务私有组件优先放在对应模块内。
- 如果涉及改造组件（业务组件/通用组件），需要用户明确说明或需要用户确认才能修改。
- 图标优先使用 `lucide-react` 或项目已有图标体系。
- 不要新增无必要的全量 barrel 文件，例如 `src/components/index.ts`。
- 单文件代码原则上不超过 1000 行；接近或超过时拆分组件、hooks、工具方法或数据文件。

## 工具、Hook 与公共逻辑

- 文件下载、格式化、转换等公共能力，若跨模块复用，应抽取到合适的 `src/lib` 工具中。
- 可复用的状态逻辑、URL 状态、弹窗状态或副作用逻辑，应优先抽取为 hook。
- 页面私有逻辑不要过早放入全局目录。

## 页面与交互原则

- 列表页、详情页通常优先使用 `SidebarLayout`。
- 项目管理、设置等首页或顶部导航场景优先使用 `TopbarLayout`。
- 如果用户没有明确页面布局，开发前需要确认使用 `topbar` 还是 `sidebar`。
- 新增、编辑流程优先使用抽屉 `drawer`，如果内容较多可以开启 `enhanced` 模式（可选弹窗`form-dialog`）。
- 导入流程使用通用导入弹窗。
- 导出流程直接触发下载。
- 详情页默认创建独立子页面并通过路由进入；仅在用户明确要求时使用抽屉详情，且优先复用 `base-detail` 组件。

## 导航规则

- 详情页一般使用 `page-action`，支持返回。
- 列表页一般使用 `page-nav`，支持多子页面跳转。
- 设置类页面一般使用 `sidebar-nav`，支持多页跳转。
- `topbar` 布局下如果有多子页面，优先使用`sidebar-nav`
- `sidebar` 布局下如果有多子页面，优先使用 `page-nav`

## API、状态与权限

- 接入 API 前阅读 `spec/10-foundation/api.md`。
- 接入权限前阅读 `spec/10-foundation/permission.md`。
- 新增全局或模块状态前阅读 `spec/10-foundation/state.md`。
- 不要在业务代码中硬编码后端 host、部署 base path、颜色值或全局 CSS。

# 代码测试
- 生成过程中的所有测试文件，如`*.test.tsx`，统一放到`src/tests`目录下。

## 质量门禁

根据改动范围选择验证命令：

```bash
npm run typecheck
npm run lint
npm run build
```

涉及测试文件或核心逻辑时，补充运行相关测试。无法运行验证时，必须说明原因和剩余风险。
