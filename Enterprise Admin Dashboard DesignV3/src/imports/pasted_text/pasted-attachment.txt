# 大模型可观测性与评估平台 — 产品功能设计文档

## 一、产品定位与背景

### 1 本平台定位

本平台定位为：

> **一款面向企业团队的 LLM 可观测性与评估平台，融合 Langfuse 的开源透明与 LangSmith 的评测深度，支持多租户隔离、自托管部署、完整评测闭环，覆盖从 Trace 追踪到评测集管理到报告输出的全流程。**

---

## 二、整体架构设计

### 2.1 两级菜单架构

```
系统层（默认入口，未选择项目时）
├── 项目管理
│   ├── 项目列表（卡片视图）
│   ├── 创建项目
│   └── 编辑 / 删除项目
└── 系统设置
    ├── 多租户管理
    ├── 用户管理
    └── 角色权限

───────────────────────────────────────────
👆 用户点击具体项目后，进入项目层 👇
───────────────────────────────────────────

项目层（选中项目后）
├── ← 返回系统层 / 项目切换器（顶部）
├── Trace 日志
├── 评测
│   ├── 评测任务
│   ├── LLM as a Judge
│   ├── 人工标注
│   └── 评测集
├── 评估器管理
└── 设置
    ├── 通用
    ├── API Keys
    ├── 连接管理（添加 LLM Provider / 模型）
    └── 评分指标
```

**交互说明：**

1. 用户首次登录，默认进入「项目管理」页面（系统层），此时左侧导航栏不展示项目级菜单。
2. 用户点击任意项目后，系统加载项目层菜单，原左侧导航栏更新为项目级功能。同时顶部导航栏出现「项目切换器」，可随时切换回系统层或其他项目。
3. 项目切换后，当前会话的工作上下文（筛选条件、选中的评测集等）不会自动跨项目保留，需用户重新配置。

### 2.2 多租户数据隔离模型

```
Tenant（租户）
├── id / name / plan / quota
├── Users[]（租户下用户）
└── Projects[]（租户下项目）

    Project（项目）
    ├── id / tenant_id / name / description / created_at
    ├── Traces[]（链路记录）
    ├── Evaluations[]（评测任务）
    ├── Datasets[]（评测集）
    ├── Evaluators[]（评估器）
    └── Config（项目配置：Providers / API Keys / Metrics）
```

- 每个租户的数据完全物理隔离（数据库层面分区或独立 schema）。
- 用户属于一个或多个租户，同一用户可在不同租户中拥有不同角色。
- 项目是租户内的最小隔离单元，同一租户下的项目之间数据不互通。

### 2.3 核心数据模型

| 实体                 | 说明                   | 主要字段                                                                                              |
| -------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| **Tenant**           | 租户                   | id, name, plan, created_at, quotas(trace_limit, user_limit)                                           |
| **User**             | 用户                   | id, email, name, tenant_id, role, status                                                              |
| **Project**          | 项目                   | id, tenant_id, name, description, created_at, last_active_at                                          |
| **Trace**            | 一次完整请求的链路记录 | id, project_id, user_id, session_id, start_time, end_time, status, total_cost, total_tokens, metadata |
| **TraceEvent**       | Trace 内每个步骤的事件 | id, trace_id, parent_id, type(llm/tool/retrieval/generic), input, output, model, latency_ms, tokens   |
| **EvaluationTask**   | 评测任务               | id, project_id, name, status, dataset_id, evaluator_id, config, created_at, completed_at              |
| **EvaluationResult** | 单条评测结果           | id, task_id, trace_id, score, details, judge_output                                                   |
| **Dataset**          | 评测集                 | id, project_id, name, source(annotation/auto/import), version, created_at                             |
| **DatasetItem**      | 评测集内的单条数据     | id, dataset_id, version, input, reference_output, metadata                                            |
| **Evaluator**        | 评估器                 | id, project_id, name, type(llm_judge/code_rule/heuristic), config, status, created_at                 |
| **AnnotationTask**   | 人工标注任务           | id, project_id, name, status, assigned_to, criteria, created_at                                       |
| **Annotation**       | 单条标注结果           | id, task_id, trace_id, annotator_id, score, labels[], comment                                         |
| **LLMProvider**      | LLM 提供商配置         | id, project_id, provider_type, endpoint, model_id, api_key_ref                                        |
| **AP IKey**          | 项目级 API Key         | id, project_id, name, key_hash, permissions, created_at, last_used                                    |

## 三、菜单功能 1：系统层（默认入口）

### 3.1 项目管理

#### 3.1.1 项目列表

**入口：** 用户登录后默认进入此页面。

**页面布局：**

- **工具栏**（页面顶部）：搜索框（按项目名称模糊搜索）、筛选器（按创建时间范围、按状态）、排序（按名称 / 创建时间 / 活跃时间）、新建项目按钮。
- **项目卡片网格**（主内容区）：每个卡片展示：
  - 项目名称（大字）
  - 项目描述（副标题，最多2行）
  - 创建时间
  - Trace 数量（实时）
  - 最后活跃时间
  - 项目状态标签（Active / Archived）
- **空状态**：无项目时显示引导创建按钮。

**操作：**

- 点击卡片进入项目（加载项目层菜单）。
- 卡片右上角「···」菜单：编辑项目、归档项目、删除项目。
- 顶部「新建项目」按钮：弹出模态框，输入项目名称（必填）和描述（选填），确认后创建。

**交互细节：**

- 删除项目需二次确认弹窗，提示「此操作将删除该项目的所有 Trace、评测任务、评测集数据，且不可恢复」。
- 归档后的项目不显示在默认列表中，通过筛选器可查看归档项目列表。

#### 3.1.2 项目切换器

**位置：** 顶部导航栏左侧。

**形态：** 下拉选择器，显示当前项目名称 + 图标，点击展开项目列表（系统层入口在列表最顶部，以分隔线分隔）。

**行为：**

- 选择系统层入口 → 退出项目，返回项目管理列表页，清空项目级菜单。
- 选择其他项目 → 切换上下文，重新加载项目层菜单，当前页签保持（如当前在 Trace 日志，切换后仍在 Trace 日志页，但数据已切换到新项目）。

### 3.2 系统设置

仅对拥有 **Admin** 或 **Owner** 角色的用户可见。

#### 3.2.1 多租户管理

**页面标题：** 租户管理（仅超级管理员可见）

**租户列表：**

| 列名       | 说明                    |
| ---------- | ----------------------- |
| 租户名称   | 租户全称                |
| 计划       | Free / Pro / Enterprise |
| Trace 配额 | 已用 / 上限             |
| 用户数     | 已用 / 上限             |
| 创建时间   | —                       |
| 操作       | 编辑 / 配额调整 / 停用  |

**创建租户：**

1. 点击「新建租户」，弹出侧边抽屉。
2. 填写字段：租户名称、联系人邮箱、选择计划。
3. 设置配额：Trace 月度上限、用户数上限。
4. 点击确认，系统创建租户并发送邀请邮件给联系人。

**配额管理：**

- 超配额时，租户下的项目停止接收新 Trace，管理员收到通知。
- 提供配额升级提示和升级链接。

#### 3.2.2 用户管理

**用户列表：**

| 列名     | 说明                            |
| -------- | ------------------------------- |
| 用户名   | 显示姓名                        |
| 邮箱     | 登录凭证                        |
| 角色     | Owner / Admin / Member / Viewer |
| 状态     | Invited / Active / Suspended    |
| 加入时间 | —                               |
| 操作     | 编辑角色 / 停用 / 删除          |

**添加用户：**

1. 点击「添加用户」，弹出模态框。
2. 输入邮箱、选择角色。
3. 选择归属租户（多租户模式下必选）。
4. 系统发送邀请链接，用户点击激活后账号生效。

**角色说明：**

- **Owner**：租户所有者，拥有所有权限，可管理租户级别设置和所有项目。
- **Admin**：管理员，可管理租户下的所有项目和用户，不可删除租户。
- **Member**：普通成员，可创建和管理自己拥有的项目，接受项目邀请。
- **Viewer**：只读用户，可查看被授权的项目，无法编辑或创建资源。

| 管理 API Keys | 写    | 写               | 写（授权项目）   | —              |
| 导出数据      | 写    | 写               | 写（授权项目）   | 读（授权项目） |

## 四、菜单功能 2：项目层（进入项目后加载）

### 4.1 Trace 日志

**模块定位：** 可观测性核心。所有 LLM 调用通过 SDK 接入后产生 Trace 数据，本模块提供 Trace 的查看、过滤和深度分析能力。

#### 4.1.1 Trace 列表页

**页面布局：**

```
┌─────────────────────────────────────────────────────────────┐
│ [时间范围] [模型] [状态] [用户] [会话] [搜索框]              │
├─────────┬─────────────────────────────────────────────────────┤
│ 筛选面板  │  Trace 列表                                       │
│          │  ┌─────────────────────────────────────────────┐ │
│ 展开/收起 │  │ [时间] [会话ID] [模型] [状态] [耗时] [成本]   │ │
│          │  │ [用户ID] [Metadata摘要]                      │ │
│          │  └─────────────────────────────────────────────┘ │
│          │  ...（分页加载，每页 50 条）                       │
└──────────┴─────────────────────────────────────────────────┘
```

**筛选维度：**

| 筛选器     | 类型              | 说明                                                             |
| ---------- | ----------------- | ---------------------------------------------------------------- |
| 时间范围   | 快捷选项 + 自定义 | 最近 15 分钟 / 1 小时 / 24 小时 / 7 天 / 30 天，或自定义起止时间 |
| 模型       | 多选下拉          | 当前项目配置过的所有模型（OpenAI / Anthropic / Gemini 等）       |
| 状态       | 多选              | Success / Error / Partial Error / Timeout                        |
| 用户 ID    | 搜索 + 多选       | 按用户维度过滤                                                   |
| 会话 ID    | 搜索              | 按会话维度过滤，同一对话链的所有 Trace 聚合                      |
| 关键词搜索 | 全文搜索          | 在输入/输出的文本内容中搜索，支持正则表达式                      |

**列表字段：**

- **时间**：该 Trace 的开始时间（精确到毫秒）。
- **会话 ID**：所属对话会话的标识，便于聚合查看同一对话的多轮交互。
- **模型**：调用的具体模型名称（如 gpt-4o、claude-3-5-sonnet）。
- **状态**：颜色标签 Success（绿）/ Error（红）/ Partial Error（橙）/ Timeout（灰）。
- **耗时**：总延迟（毫秒），超过阈值（如 30s）标红提示。
- **成本**：该次请求的估算 token 消耗费用（美元），按项目配置的 Provider 计费模型计算。
- **用户 ID / Metadata 摘要**：快速定位请求来源。

**交互行为：**

- 点击任意行 → 展开该 Trace 的详情面板（行内展开，或跳转详情页，由用户偏好设置决定）。
- 勾选左侧复选框 → 批量操作：添加到评测集 / 发起人工标注 / 导出选中 Trace。
- 分页：默认每页 50 条，支持翻页和「加载更多」滚动加载。

#### 4.1.2 Trace 详情页

**布局：左侧层级调用树 + 右侧详情面板**

**左侧 — 层级调用树（Span Tree）：**

```
Root Trace
├── LLM Call: gpt-4o
│   ├── Tool Call: search_web
│   │   └── Retrieval: vector_search(top_k=5)
│   └── Tool Call: calculator
└── LLM Call: gpt-4o (final)
```

- 每个节点显示类型图标（LLM / Tool / Retrieval / Generic）、名称、耗时、子节点数。
- 点击节点 → 右侧面板展示该节点的详细信息。
- 支持折叠/展开任意分支。
- 高亮错误节点（Error 状态标红）。

**右侧 — 详情面板（Tab 切换）：**

- **输入（Input）Tab**：该步骤的完整输入 JSON，语法高亮展示，支持折叠长文本。
- **输出（Output）Tab**：该步骤的完整输出 JSON，支持 Markdown 预览（如果输出为 Markdown 格式）。
- **元数据（Metadata）Tab**：关联的用户 ID、会话 ID、标签（Tags）、自定义 metadata 键值对。
- **Token 消耗 Tab**：Prompt Tokens / Completion Tokens / 总 Tokens，按 Provider 计费模型计算费用。
- **比较（Compare）Tab**：可选「对比另一条 Trace」，左右分栏展示两条 Trace 的同层级节点对比，高亮差异字段。

**顶部操作栏：**

- 「添加到评测集」：将该 Trace 的完整输入/输出作为评测样本。
- 「发起标注」：将该 Trace 发送到人工标注流程。
- 「复制 Trace ID」：一键复制。
- 「导出」：导出该 Trace 的 JSON 文件。

#### 4.1.3 搜索能力

**全文搜索：**

- 支持在 Trace 的 input/output/metadata 中进行关键词匹配。
- 支持正则表达式（以 `/` 开头和结尾触发正则模式）。
- 搜索结果高亮匹配片段，点击结果直接跳转到对应 Trace 的详情页。

**JSON Path 查询（高级模式）：**

- 输入 JSONPath 表达式（如 `$.metadata.user_id`），精确提取 Trace 中的特定字段进行过滤。
- 适合有结构化 metadata 的高级用户。

### 4.2 评测模块

**模块定位：** 评测是平台的核心价值模块，提供从评测集构建、评测任务执行到结果分析的全流程支持。本模块与 Trace 日志深度集成，支持从生产流量直接生成训练数据。

#### 4.2.1 评测任务

**4.2.1.1 评测任务列表页**

**页面布局：**

| 任务名称          | 状态      | 评测集        | 评估器         | 进度    | 创建时间   | 操作               |
| ----------------- | --------- | ------------- | -------------- | ------- | ---------- | ------------------ |
| Q&A 准确性评测 v2 | Completed | medical-qa-v3 | accuracy-judge | 200/200 | 2026-06-01 | 查看 / 报告 / 重跑 |

**状态说明：**

| 状态      | 含义                             | 视觉          |
| --------- | -------------------------------- | ------------- |
| Pending   | 已创建，等待调度                 | 灰色          |
| Running   | 执行中，显示进度百分比           | 蓝色 + 进度条 |
| Completed | 全部完成                         | 绿色          |
| Failed    | 执行失败（部分失败记录在详情中） | 红色          |
| Cancelled | 用户手动取消                     | 灰色虚线      |

**创建评测任务：**

1. 点击「新建评测任务」，弹出配置向导。
2. **Step 1 — 基本信息**：输入任务名称（必填）、描述（选填）。
3. **Step 2 — 选择评测集**：从现有评测集列表中选择，或新建评测集后返回选择。
4. **Step 3 — 选择评估器**：选择已上线的评估器（可多选，多个评估器将分别在同一条数据上产生多个评分维度）。
5. **Step 4 — 配置执行参数**：
   - 并发数（控制同时发起的请求数量）
   - 重试次数（单条数据失败时的重试策略）
   - 是否启用缓存（相同输入避免重复评测）
6. 点击确认，任务进入 Pending 状态并开始调度。

**4.2.1.2 评测任务详情页**

**执行日志面板（可折叠）：**

- 实时滚动显示每条数据的评测状态。
- 每行格式：`[时间戳] [数据ID] [状态] [耗时] [评分: X/10]`。

**评测结果汇总：**

- **总体评分**：加权平均分（大字展示），与上一版本的对比（↑↓ 百分比）。
- **评分分布直方图**：各评分档位（0-2 / 3-5 / 6-8 / 9-10）的样本数量柱状图。
- **评估维度雷达图**：当使用多个评估器时，各维度的平均得分雷达图。
- **典型 Bad Case**：评分最低的前 5 条数据，自动展示 input / reference_output / actual_output / judge_feedback。

**逐条结果查看：**

- 表格形式展示所有评测结果，支持排序（按评分 / 按耗时 / 按时间）。
- 每行：数据ID、评分、评估器名称、耗时、详情操作。
- 点击详情 → 展开该条数据的完整评测报告（input / reference / actual / judge 评分理由）。

**4.2.1.3 报告生成**

- 点击「生成报告」→ 选择格式（PDF / HTML）。
- 报告内容包含：
  - 任务配置摘要（评测集来源、评估器信息、执行参数）
  - 总体评分与分布
  - 各维度评分详情
  - 典型 Bad Case 列表
  - 改进建议（基于高频失败维度的自然语言总结）
- 报告可下载或在浏览器内预览。

#### 4.2.2 LLM as a Judge

**模块定位：** 基于大模型作为自动化评测员，对 LLM 输出进行质量打分，替代或辅助人工评测。

**4.2.2.1 评测器配置**

**配置表单：**

| 配置项           | 说明                                                 | 示例                       |
| ---------------- | ---------------------------------------------------- | -------------------------- |
| 评测器名称       | 标识该评测器                                         | medical-accuracy-judge     |
| Judge 模型       | 选择用于评测的模型                                   | gpt-4o / claude-3-5-sonnet |
| 评分范围         | 分数下限 ~ 上限                                      | 0 ~ 10                     |
| 评测 Prompt 模板 | 系统 Prompt，指导 Judge 如何评分（支持 Jinja2 变量） | 见下方示例                 |
| 评分维度         | 可添加多个维度（每次评测输出多维分数）               | 准确性 / 相关性 / 安全性   |

**Prompt 模板示例（Jinja2 格式）：**

```jinja2
你是一位专业的医学问答质量评估专家。请根据以下参考回答和实际回答，对模型输出的质量进行评分。

## 参考回答：
{{ reference_output }}

## 实际回答：
{{ actual_output }}

## 问题：
{{ input }}

请从以下三个维度分别打分（每个维度 0-10 分）：
1. 准确性（回答的事实正确性）
2. 相关性（回答是否切题）
3. 安全性（回答是否有害信息）

请以 JSON 格式输出：
{
  "accuracy": <分数>,
  "relevance": <分数>,
  "safety": <分数>,
  "reasoning": "<评分理由>"
}
```

- 在线 Prompt 编辑器，支持 Jinja2 语法高亮和变量预览（点击「预览变量」显示当前评测集中所有可用字段）。
- 提供 Prompt 模板库（预设 10+ 场景模板：摘要质量、问答准确性、代码正确性等），用户可直接引用并修改。

**4.2.2.2 运行模式**

| 模式     | 说明                                | 触发方式                                          |
| -------- | ----------------------------------- | ------------------------------------------------- |
| 离线评测 | 基于选定的评测集批量执行评测        | 创建评测任务时选择「离线」，关联评测集            |
| 在线评测 | 在生产 Trace 流入时实时采样执行评测 | 在项目设置中开启「在线评测」，配置采样率（如 5%） |

**在线评测配置：**

- 采样率设置（0.1% ~ 100%）。
- 触发条件：可设置条件触发（如错误率超过阈值时自动开启全量评测）。
- 过滤条件：可按模型 / 用户 / 会话 ID 维度决定是否触发评测。
- 成本控制：设置月度在线评测预算，超预算后自动暂停并告警。

**4.2.2.3 结果展示**

- 每条数据的 Judge 结果包含：
  - **各维度评分**：以分数 + 色条（颜色渐变：红→黄→绿）展示。
  - **置信度**：Judge 模型对评分结果的置信度（通过多次采样或 Chain-of-Thought 推理得出）。
  - **推理依据**：Judge 给出该分数的具体理由（引用原始输出中的具体片段）。
  - **JSON 输出**：Judge 的原始结构化输出（便于调试 Prompt）。
- 支持按评分排序，快速定位低分数据。

#### 4.2.3 人工标注

**模块定位：** 在自动化评测不足以覆盖的维度（如主观质量、创意评估、领域专业性），通过人工标注提供 ground-truth 标注数据，同时构建高质量评测集。

**4.2.3.1 标注任务创建**

1. 点击「新建标注任务」。
2. **选择待标注数据**：
   - 从 Trace 列表中勾选（可多选）。
   - 或从现有评测集中选择特定子集。
   - 支持按条件自动筛选（如「选择所有评分 < 5 的数据」）。
3. **设置标注维度**：
   - 可选择预设维度（准确性 / 相关性 / 完整性 / 安全性）或自定义维度。
   - 每个维度设置评分类型：分数（0-10 滑块）、单选标签（好/中/差）、多选标签（可同时选择多个标签）。
4. **分配标注者**：
   - 指定用户（单人标注）或分配给角色（多人标注，相同数据由多人标注以计算一致性）。
   - 设置每条数据需要的标注人数（1-N 人）。
5. 点击确认，任务创建，进入「待领取」状态。

**4.2.3.2 标注界面**

**布局：** 左右分栏 + 底部操作区

```
┌────────────────────────────────────────────────────────────────┐
│ [返回任务列表]  标注任务: 医疗QA质量标注 v1    进度: 45/100      │
├──────────────────────────────┬─────────────────────────────────┤
│        输入（Prompt）         │         输出（模型回答）         │
│  （左侧只读，不可编辑）         │  （左侧只读，不可编辑）          │
│                              │                                 │
│  问题：流感与普通感冒的区别？   │  回答：流感（流感病毒）...       │
│                              │                                 │
├──────────────────────────────┴─────────────────────────────────┤
│  参考答案（Ground Truth）：（如有）                              │
│  专家标准答案：...                                              │
├────────────────────────────────────────────────────────────────┤
│  标注维度：                                                      │
│  准确性：  ○───●────○  7/10                                     │
│  相关性：  ○──●─────○  8/10                                     │
│  安全性：  ○──────●─○  9/10                                    │
│  问题标签：☐ Factual Error  ☐ Hallucination  ☐ Incomplete      │
│  总体评价：[                                                 ]  │
├────────────────────────────────────────────────────────────────┤
│                      [保存并下一条]  [跳过]                      │
└────────────────────────────────────────────────────────────────┘
```

**交互说明：**

- 左右对比模式下，Prompt 和回答并排展示，减少标注者切换成本。
- 滑块实时显示数值（0-10），同时显示该维度在项目内的历史均值作为参考基准。
- 支持键盘快捷键（←/→ 切换数据，1-9 设置评分）。
- 标注过程中可添加笔记，不强制要求。

**4.2.3.3 标注流程管理**

**任务状态流转：**

```
待领取 → 进行中 → 待审核 → 已通过 / 已打回（重新标注）
```

- **待领取**：任务已创建，等待标注者领取。
- **进行中**：至少一名标注者已领取并开始标注。
- **待审核**：所有标注者完成标注，任务流转到审核者。
- **已通过**：审核者确认标注质量，数据进入评测集。
- **已打回**：审核者要求重新标注，任务退回给标注者。

**一致性指标：**

- 当同一数据有多人标注时，展示各标注者之间的评分一致性（如 Cohen's Kappa 或 Krippendorff's Alpha）。
- 一致性低于阈值（如 0.6）的数据自动标记为「需仲裁」，由高级审核员裁定最终值。

**审核界面（标注管理视角）：**

- 查看所有标注者的独立评分，以及综合评分。
- 对单条标注结果进行「通过 / 打回」操作，并填写打回理由。
- 支持批量审核。

#### 4.2.4 评测集管理

**模块定位：** 评测集是评测任务的输入数据载体，来源于人工标注、模型生成或外部导入。本模块负责评测集的创建、编辑、版本管理和导入导出。

**4.2.4.1 评测集列表**

| 评测集名称        | 来源     | 样本数 | 当前版本 | 创建时间   | 操作                      |
| ----------------- | -------- | ------ | -------- | ---------- | ------------------------- |
| medical-qa-v3     | 人工标注 | 200    | v3       | 2026-05-15 | 查看 / 编辑 / 导出 / 删除 |
| auto-generated-v1 | 模型生成 | 500    | v1       | 2026-05-20 | 查看 / 导出               |
| import-chatbot    | CSV导入  | 100    | v1       | 2026-04-10 | 查看 / 导出 / 删除        |

**来源说明：**

| 来源        | 说明                                                        |
| ----------- | ----------------------------------------------------------- |
| 人工标注    | 由人工标注流程产出，数据质量最高                            |
| 模型生成    | 通过 LLM 自动生成（如 few-shot prompting 生成大量合成数据） |
| 导入        | 从外部文件（JSON/CSV）导入                                  |
| 从 Trace 来 | 从 Trace 日志中批量选择，导出一条或多条 Trace 作为评测样本  |

**4.2.4.2 评测集详情与编辑**

**数据字段结构（每条数据）：**

```json
{
  "id": "item_001",
  "version": "v3",
  "input": "问题文本",
  "reference_output": "参考答案（可选）",
  "metadata": {
    "source": "trace_abc123",
    "model": "gpt-4o",
    "created_at": "2026-06-01T10:00:00Z"
  }
}
```

**在线编辑功能：**

- **单条查看**：点击任意数据行，展开详情，可修改 input / reference_output / metadata。
- **批量编辑**：
  - 多选数据 → 批量修改 metadata 字段。
  - 批量设置标签（如批量标记「医疗领域」）。
- **版本管理**：
  - 每次对数据的修改操作均记录为新版本（v1 → v2 → v3）。
  - 版本历史面板：查看每个版本的修改内容（diff 视图）和修改人。
  - 支持回滚到任意历史版本（生成新版本，不覆盖历史）。
  - 支持版本对比：选择任意两个版本，diff 展示数据差异。

**4.2.4.3 导入与导出**

**导入：**

- 支持格式：JSON（单文件或 NDJSON 每行一条）、CSV（含表头）。
- 导入向导：选择文件 → 字段映射（将 CSV 列映射到 input / reference_output / metadata 字段）→ 预览前 5 条 → 确认导入。
- 导入校验：缺失必填字段时提示，数据格式错误时提供修正建议。
- 支持增量导入（追加到现有评测集）和全量替换（覆盖现有数据）。

**导出：**

- 支持格式：JSON、CSV。
- 可选择导出全部数据或特定版本。
- 导出文件自动命名为 `{评测集名称}_{版本}_{日期}.json`。

### 4.3 评估器管理

**模块定位：** 评估器是评测任务的核心执行单元。本模块展示当前项目内所有已上线的评估器，并支持创建和管理自定义评估器。

#### 4.3.1 评估器列表

| 评估器名称       | 类型      | 状态 | 累计使用次数 | 创建时间   | 操作               |
| ---------------- | --------- | ---- | ------------ | ---------- | ------------------ |
| accuracy-judge   | LLM Judge | 上线 | 1,234        | 2026-05-01 | 编辑 / 下线 / 删除 |
| json-valid-check | Code Rule | 上线 | 5,678        | 2026-05-03 | 编辑 / 下线 / 删除 |
| response-length  | Heuristic | 下线 | 230          | 2026-04-20 | 上线 / 编辑 / 删除 |

**类型说明：**

| 类型          | 说明                              | 适用场景                                  |
| ------------- | --------------------------------- | ----------------------------------------- |
| **LLM Judge** | 使用大模型对输出进行主观/客观评分 | 准确性、相关性、有害性等难以规则化的维度  |
| **Code Rule** | 确定性代码规则，检查特定条件      | JSON 结构验证、必需字段检查、代码编译测试 |
| **Heuristic** | 启发式函数，基于指标计算评分      | 响应长度、Token 数量、特定模式匹配        |

#### 4.3.2 自定义评估器创建

**创建流程（三步向导）：**

**Step 1 — 选择类型**

- 点击「新建评估器」→ 选择类型（LLM Judge / Code Rule / Heuristic）。

**Step 2 — 编写评估逻辑**

- **LLM Judge 类型**：
  - 选择 Judge 模型。
  - 编辑评测 Prompt 模板（与 4.2.2 中相同的 Prompt 配置）。
  - 设置输出格式（JSON Schema 或自由文本解析规则）。
  - 配置评分提取规则（告诉系统如何从 Judge 输出中提取分数）。

- **Code Rule 类型**：
  - 提供在线代码编辑器（JavaScript / Python 语法高亮）。
  - 编写评估函数签名：`function evaluate(input, output, reference, metadata) → { score: number, passed: boolean, reason: string }`。
  - 提供测试面板：输入示例数据 → 点击「运行测试」→ 查看评估结果。
  - 每次修改后需重新测试通过才可保存。

- **Heuristic 类型**：
  - 选择预设函数（Response Length / Token Count / Contains Keyword / JSON Parse）。
  - 配置参数（如 Contains Keyword：指定关键词列表）。
  - 或通过 Code Rule 方式编写自定义函数。

**Step 3 — 预览测试与上线**

- 使用当前项目中的任意 Trace 数据或手动输入测试数据。
- 执行评估器并查看结果（评分、reasoning）。
- 确认无误后点击「上线」，评估器进入上线状态，可在评测任务中被选用。
- 上线前可设置「灰度模式」：新评估器先在 10% 的流量上运行，观察结果无异常后再全量上线。

#### 4.3.3 评估器版本与变更管理

- 每次修改评估器的配置（Prompt / 代码 / 参数）均生成新版本。
- 版本历史支持快速回滚。
- 评测任务运行时固定关联特定版本，不会因评估器更新而影响历史评测结果的可复现性。

#### 4.4.2 API Keys

**API Key 列表：**

| 完整性   | 数值（0-10） | 20%      | 回答是否完整覆盖问题 |

- 支持添加自定义维度（如「创意性」「表达流畅度」等）。
- 设置各维度权重，用于计算评测任务的综合得分（加权平均）。
- 权重总和应等于 100%，系统自动校验。

### 6.2 术语表

| 术语                          | 说明                                                          |
| ----------------------------- | ------------------------------------------------------------- |
| Trace                         | 一次完整的 LLM 请求链路记录，包含调用树中所有步骤             |
| Span / TraceEvent             | Trace 内的单个调用步骤（如一次 LLM 调用或一次 Tool 调用）     |
| Dataset / 评测集              | 用于评测的输入-参考输出数据集，支持版本管理                   |
| Evaluator / 评估器            | 执行评测逻辑的组件，分为 LLM Judge、Code Rule、Heuristic 三类 |
| Evaluation Task / 评测任务    | 一次完整的评测执行过程，对应一个 Dataset 和一个 Evaluator     |
| LLM-as-Judge                  | 用大模型作为评测员对其他 LLM 输出进行评分                     |
| Human Annotation / 人工标注   | 由人工对 Trace 数据进行质量标注，构建 Ground Truth            |
| MCP / Model Context Protocol  | Anthropic 提出的 AI Agent 与外部工具/数据源的通信协议         |
| Multi-tenancy / 多租户        | 同一系统支撑多个独立租户，租户间数据隔离                      |
| Offline Evaluation / 离线评测 | 基于历史数据集批量执行评测                                    |
| Online Evaluation / 在线评测  | 对生产流量实时采样并执行评测                                  |
