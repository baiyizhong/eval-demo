# 人工标注“保存并下一条”设计

## 当前问题

单条标注页保存后复用了普通分页导航：按进入详情页时的页码和筛选条件重新查询列表，再取当前项的相邻数据。当前项保存后会变成 `COMPLETED`；当原筛选条件包含 `PENDING` 时，当前项已不在结果中，索引为 `-1`，页面会误判没有下一条。即使能找到相邻项，也只覆盖当前分页，并且不保证状态为未标注。

## 目标行为

点击“保存并下一条”后：

1. 保存当前评分并完成当前标注项。
2. 独立查询整个标注队列中 `status=PENDING` 的数据。
3. 使用 `page=1&pageSize=1` 取得后台排序后的第一条未标注数据。
4. 找到数据后跳转到其单条标注页。
5. 跳转时将 URL 状态归一为 `page=1`、当前 `pageSize`、`status=PENDING`，避免详情页导航上下文与实际数据不一致。
6. 没有未标注数据时提示“当前标注队列已全部完成”。

## 边界

- 顶部“上一条/下一条”继续使用原列表分页导航，不改变其语义。
- “保存”按钮只保存当前项，不自动跳转。
- 不新增后端接口，复用现有标注项列表接口。
- 不继承关键字、对象类型、完成人等原列表筛选，确保搜索范围是整个队列。

## 测试

- API helper 必须请求 `page=1`、`pageSize=1`、`status=['PENDING']`。
- 有结果时返回第一条未标注数据；没有结果时返回 `null`。
- 单条标注页的 `saveNext` 分支必须调用新 helper，不再调用普通导航 helper。
- 保存后跳转 URL 必须使用未标注队列上下文。
