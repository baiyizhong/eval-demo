# 前端递增轮询公共策略设计

## 背景

自动评测列表当前通过固定 `refetchInterval: 3000` 每 3 秒请求一次任务列表。该轮询不会主动结束，会产生不必要的持续请求。

## 目标

- 页面首次请求不计入轮询次数。
- 首次请求完成后，依次等待 `2s`、`4s`、`8s`、`16s`、`32s` 发起轮询。
- 最多轮询 5 次，第 5 次轮询完成后停止。
- 成功和失败的轮询请求均计入次数，避免异常接口无限轮询。
- 将间隔计算抽取为公共策略，供其他 React Query 查询复用。
- 首次切换到未访问过的分页时，新分页对应新的 React Query 查询实例，重新开始轮询。
- 返回已访问分页时可能复用缓存中的轮询计数，不额外重置。

## 方案

新增无 React 状态依赖的公共递增轮询策略函数。策略读取 React Query 查询实例中已完成的数据更新和错误更新次数，用查询完成总次数区分首次请求与后续轮询，并返回下一次轮询间隔或 `false`。

默认参数：

- 初始间隔：`2000ms`
- 递增倍数：`2`
- 最大轮询次数：`5`

计算结果：

| 已完成请求 | 含义 | 下一次间隔 |
| --- | --- | --- |
| 0 | 首次请求尚未完成 | `2000ms` |
| 1 | 首次请求完成 | `2000ms` |
| 2 | 第 1 次轮询完成 | `4000ms` |
| 3 | 第 2 次轮询完成 | `8000ms` |
| 4 | 第 3 次轮询完成 | `16000ms` |
| 5 | 第 4 次轮询完成 | `32000ms` |
| 6 | 第 5 次轮询完成 | `false`，停止 |

React Query 在首次请求完成后重新计算 `refetchInterval`，因此首次网络请求不会被计入 5 次轮询。查询失败时使用错误更新次数参与计算。

## 接入范围

1. 公共目录新增递增轮询策略及其类型。
2. `DataTable` 的 `request.refetchInterval` 类型从仅支持 `number | false` 扩展为同时支持 React Query 动态回调。
3. 自动评测列表将固定 3 秒间隔替换为公共递增轮询策略。
4. 不修改详情页当前仅在 `RUNNING` 状态下轮询的行为。

## 测试

- 验证首次请求完成后返回 `2000ms`。
- 验证 5 次轮询间隔依次为 `2000/4000/8000/16000/32000ms`。
- 验证第 5 次轮询完成后返回 `false`。
- 验证失败请求同样推进轮询次数。
- 验证自动评测列表接入公共策略，不再配置固定 `3000ms`。
