# 定时任务前端原型设计

## 背景

当前自动评测已经具备手动创建和执行能力，但定时任务的交互仍在探索阶段。为了快速调整信息架构、创建流程、任务列表和执行日志，本次只实现前端页面和本地 mock 数据，不实现后端逻辑。

本设计新增一个项目级一级菜单“定时任务”，用于承载自动评测类定时任务的创建、查看、编辑、暂停、恢复、手动执行和执行日志查看。除新增菜单入口、路由注册和新模块自身代码外，不修改现有功能页面。

## 目标

- 在项目侧边栏新增一级菜单“定时任务”，与“应用观测 / 应用评测 / 项目设置”同级。
- 新增独立定时任务页面，包含“任务列表”和“执行日志”两个子页面。
- 通过抽屉完成任务创建、查看和编辑。
- 支持自动评测类型任务的基础信息、评估器选择、数据来源选择、Trace 时间窗口联动和采样提醒。
- 使用前端本地 mock 文件保存初始任务和日志数据，页面运行时使用内存状态验证交互。
- 保持新模块与现有“应用评测-自动评测”页面隔离，避免影响已有功能。

## 非目标

- 不实现后端接口。
- 不创建真实定时任务。
- 不创建真实自动评测任务、评测报告或执行记录。
- 不新增或修改数据库表结构。
- 不修改 `langfuse/`、`dify/` 目录。
- 不重构现有自动评测页面。

## 创建与编辑流程

点击“创建任务”后打开右侧抽屉。

抽屉建议宽度：

- 桌面端约 `720px`。
- 小屏幕占满宽度。

抽屉使用两步 Stepper。

### 第一步：基础信息

字段：

- 任务类型：目前只有 `自动评测` 一个选项。
- 任务名称：必填。
- 任务描述：可选。
- Score Name：选择自动评测时显示，必填。
- 执行频率：
  - 单次执行。
  - 周期性执行。

周期性执行配置使用中文友好表单：

- 每 N 分钟。
- 每 N 小时。
- 每天几点。
- 每周几几点。
- 高级 cron。

高级 cron 支持直接输入 cron 表达式，并显示中文解释区域。第一版不需要覆盖所有复杂 cron 边界，无法解释时展示“自定义 cron，将按表达式触发”。

### 第二步：自动评测配置

当任务类型为自动评测时展示。

包含两个子区块：

1. 选择评估器
2. 选择评测数据来源

评估器选择参考现有“应用评测-自动评测”新建页：

- 展示 Workflow 类型评估器。
- 支持搜索。
- 显示名称、描述、版本、变量信息。
- 选择后展示变量映射区。

数据来源规则：

- 单次执行：支持 `Trace 过滤` 和 `数据集`。
- 周期性执行：只支持 `Trace 过滤`。

数据集来源第一版使用 mock 列表，支持搜索和单选。

Trace 过滤包含：

- 环境。
- Tags。
- User ID。
- Session ID。
- 时间窗口。
- 预估命中数。
- 样本预览入口。
- 采样率。

## Trace 时间窗口联动

单次执行时，Trace 时间窗口是固定窗口：

- 快捷范围。
- 小时级开始时间。
- 小时级结束时间。

周期性执行时，Trace 时间窗口是动态窗口，并与执行频率联动：

- 每 N 分钟：默认窗口为最近 N 分钟。
- 每 N 小时：默认窗口为最近 N 小时。
- 每天几点：默认窗口为上一天 0 点到当天 0 点。
- 每周几几点：默认窗口为上一周期的 7 天。
- 高级 cron：默认使用“最近 N 分钟 / 小时 / 天”的动态窗口配置。

页面文案需要明确区分：

- 单次执行：使用当前选择的固定时间范围。
- 周期性执行：每次触发时动态计算时间范围。

## 采样与性能提醒

Trace 过滤变化后展示“预估命中”。

本次预估命中使用 mock 计算，不请求后端。

当单次实际处理样本数超过 1000 时展示性能提醒。

单次实际处理样本数计算：

```text
estimatedCount * sampleRate / 100
```

提醒文案建议：

```text
本次预计处理超过 1000 条样本，可能影响执行耗时和系统性能。建议降低采样率或缩小 Trace 筛选范围。
```

该提醒同时适用于：

- 单次执行的固定 Trace 范围。
- 周期性执行中每次触发预计会处理的动态窗口。

## 任务列表

列：

- 任务名称。
- 描述。
- 任务类型。
- 执行频率。
- 任务状态。
- 下次执行时间。
- 操作。

状态：

- `未启动`
- `运行中`
- `已暂停`
- `执行成功`
- `执行失败`

操作：

- 查看 / 编辑。
- 暂停任务。
- 恢复任务。
- 手动执行。
- 删除。

操作行为：

- 查看 / 编辑：打开同一个抽屉，加载任务数据。
- 暂停任务：状态改为已暂停，下次执行时间显示为 `--`。
- 恢复任务：状态改为未启动，并重新计算 mock 下次执行时间。
- 手动执行：生成一条执行日志，并更新任务最近状态。
- 删除：从本地任务列表移除，关联日志保留，日志中显示任务已删除。

## 执行日志

执行日志页展示每次手动或模拟计划触发的执行记录。

列：

- 任务名称。
- 触发方式。
- 任务类型。
- 执行状态。
- 开始时间。
- 结束时间。
- 执行时长。
- 处理样本数。
- 关联自动评测任务。
- 关联评测报告。

触发方式：

- 手动执行。
- JOB 触发。

执行状态：

- 运行中。
- 成功。
- 失败。

自动评测类型任务的执行日志需要模拟关联内容：

- 自动评测任务路径。
- 评测报告路径。

这些路径指向现有页面格式，但不创建真实后端数据。若用户点击，可展示提示或打开路径后由现有页面处理 404 / 空状态。

周期性自动评测任务触发时，模拟生成的自动评测任务名称规则：

```text
【JOB触发】定时任务名称-YYYYMMDDHHmm
```

示例：

```text
【JOB触发】xxxx-202607090100
```

## Mock 执行规则

手动执行：

- 点击后立即生成一条日志。
- 默认模拟成功。
- 可在日志中展示执行耗时和样本数。
- 样本数来自当前数据来源预估，并应用采样率。

周期性 JOB 触发：

- 第一版不需要真实计时器。
- 列表行操作提供“模拟 JOB 触发”，用于验证周期性执行日志和命名规则。
- “模拟 JOB 触发”仅操作页面内存中的 mock 数据，不依赖后端。

## 错误与空状态

任务列表空状态：

- 展示“暂无定时任务”。
- 提供“创建任务”按钮。

执行日志空状态：

- 展示“暂无执行日志”。
- 提示可通过手动执行任务生成日志。

表单校验：

- 任务名称必填。
- Score Name 在自动评测类型下必填。
- 周期性执行必须配置有效频率。
- 高级 cron 为空时不能保存。
- 第二步必须选择评估器。
- 第二步必须选择数据来源。
- Trace 过滤至少需要有时间窗口。
- 数据集来源必须选择数据集。
