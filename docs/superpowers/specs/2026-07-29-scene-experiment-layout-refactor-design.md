# 场景试验功能布局重构设计

## 1. 目标与范围

本次只调整 `pa-eval-frontend` 的产品功能布局与前端交互组合，不实现后端服务，不新增真实后端 API，不修改数据库，也不修改 `langfuse/`、`dify/`。

目标：

1. 将项目侧边栏一级菜单“场景管理”改为“场景试验”。
2. 将项目级场景试验报告集中到“场景试验”功能 Tab。
3. 保留原场景管理的新增、查询、查看和编辑能力。
4. 保留数据集详情中的“试验报告”Tab 和“场景试验”快捷按钮。
5. 复用现有试验提交、报告轮询、基线、聚合和对比规则，只调整入口、布局和上下文。

## 2. 信息架构

统一入口继续使用：

```text
/projects/:projectId/scenes
```

侧边栏菜单名称改为“场景试验”，保持 `activeMatch: 'prefix'`，使场景详情、报告详情和分析页面仍能正确高亮所属模块。

入口页面使用 `Page + PageNav`，提供两个同级功能 Tab：

- `场景试验`：默认 Tab，展示项目级试验报告列表。
- `场景管理`：展示原场景管理页面能力。

Tab 状态通过 URL 查询参数保存：

```text
/projects/:projectId/scenes?tab=experiments
/projects/:projectId/scenes?tab=management
```

未提供或提供非法 `tab` 时默认进入 `experiments`。

现有场景详情路由保持不变：

```text
/projects/:projectId/scenes/:sceneId
```

## 3. 场景试验 Tab

### 3.1 顶部操作

右上角提供：

- 刷新按钮：刷新当前项目的数据集、试验报告和基线相关查询。
- 新建场景试验：打开统一的五步增强型抽屉。

### 3.2 项目级报告列表

采用项目级平铺表格，不按数据集分组。列表沿用现有 `DataTable` 交互和报告列展示，并增加“数据集”列。

展示和操作包括：

- 试验名称。
- 所属数据集。
- 场景与 Webhook 服务。
- 状态和执行进度。
- 执行轮次。
- 评分结果。
- 完成时间。
- 基线相关操作。
- 勾选已完成报告后执行聚合报告或对比分析。

筛选能力：

- 搜索试验名称、场景名称、Webhook 服务或数据集名称。
- 按数据集筛选。
- 按报告状态筛选。
- 排序和分页在合并后的项目级结果上执行。

### 3.3 前端数据组合

现有接口只支持按数据集查询报告。本次不新增后端契约，项目级列表由前端完成组合：

1. 查询当前项目的数据集列表。
2. 并行查询每个数据集的试验报告。
3. 将报告与数据集名称、类型等展示信息关联。
4. 合并结果后执行项目级搜索、筛选、排序和分页。

部分数据集报告查询失败时，保留成功结果，并显示非阻塞错误提示；全部失败时显示错误状态和重试入口。

该方案仅用于当前前端原型。后续真实后端提供项目级分页接口时，可替换数据源而不改变表格和页面交互。

### 3.4 分析规则不变

- 基线作用域仍包含数据集，不允许跨数据集设置或替换基线。
- 聚合报告仍要求选择同一次试验的至少两份已完成报告。
- 对比分析仍要求报告属于同一数据集、同一场景和同一服务系列。
- 跨数据集或不满足规则的选择继续使用现有 toast 提示。

## 4. 场景管理 Tab

场景管理 Tab 复用原场景管理页面能力，不改变业务逻辑：

- 新增场景。
- 按名称搜索场景。
- 按可用状态筛选。
- 查看场景详情。
- 编辑场景。
- 启用或停用场景。
- 删除场景，历史报告继续读取配置快照。

场景新增和编辑继续使用现有增强型抽屉；场景详情继续使用独立路由页面。

## 5. 统一新建场景试验抽屉

项目级入口和数据集详情快捷入口复用同一个增强型抽屉和同一套状态、校验、提交逻辑，仅通过入口上下文决定数据集是否可切换。

抽屉精简为五步：

### 5.1 第一步：选择场景

- 填写试验名称。
- 填写试验描述。
- 单选一个可用场景。
- 展示场景描述、Webhook 数量和默认运行参数摘要。
- 无可用场景时展示“前往场景管理”。

切换场景时：

- 保留试验名称和描述。
- 清空已选评估器和 Webhook。
- 使用新场景的默认运行参数覆盖当前运行参数。

### 5.2 第二步：选择数据集

项目级入口：

- 展示当前项目数据集的紧凑表格。
- 支持按名称或描述搜索。
- 支持按数据集类型筛选。
- 支持分页。
- 使用单选控件，只能选择一个数据集。
- 选中后展示数据集类型、有效数据量和更新时间摘要。

数据集详情快捷入口：

- 自动选择当前数据集。
- 保留完整第二步，但以只读摘要展示当前数据集。
- 不允许切换到其他数据集。

无数据集时展示空状态和“前往数据集管理”，不在抽屉内新增数据集。

### 5.3 第三步：选择评估器

- 仅展示当前项目的评估器。
- 支持多选和查看详情。
- 默认不选择。
- 至少选择一个评估器后才能继续。

### 5.4 第四步：执行配置

将原“选择 Webhook”和“运行参数”合并为一步。

布局：

- 宽屏采用左侧 Webhook、右侧运行参数的双栏布局。
- 窄屏自动变为单栏，避免内容重叠和横向溢出。

Webhook：

- 从第一步所选场景带出全部 Webhook 服务。
- 支持多选和查看服务详情。
- 默认不选择，要求用户明确勾选。
- 至少选择一个 Webhook 服务。

运行参数：

- 从场景默认参数自动带出。
- 允许仅对本次试验覆盖并发数、超时时间、重试次数和执行轮次。
- 沿用现有参数范围校验。

### 5.5 第五步：确认执行

汇总展示：

- 试验名称和描述。
- 场景。
- 数据集和有效数据量。
- 评估器和评分变量。
- Webhook 服务及将生成的服务级报告。
- 最终运行参数。
- 预计调用量。

预计调用量继续使用：

```text
有效数据项数量 × Webhook 服务数量 × 执行轮次
```

数据集没有有效数据项时禁止提交，并展示明确原因。

## 6. 两类入口的提交结果

项目级入口提交成功后：

- 关闭抽屉。
- 保持在“场景试验”Tab。
- 刷新项目级报告列表，新报告进入排队状态。

数据集详情入口提交成功后：

- 关闭抽屉。
- 切换到当前数据集的“试验报告”Tab。
- 刷新当前数据集报告列表。

数据集详情继续保留：

- “试验报告”Tab，仅展示当前数据集的报告。
- “场景试验”按钮，用当前数据集快速发起试验。

## 7. 报告详情与返回来源

报告详情、聚合报告和对比分析页面继续复用现有实现。通过 URL 查询参数传递来源上下文，不新增全局状态。

来源规则：

- 从项目级列表进入时，返回 `/projects/:projectId/scenes?tab=experiments`。
- 从数据集详情进入时，返回 `/projects/:projectId/evaluation/datasets/:datasetId?tab=reports`。
- 未提供合法来源时，根据路由中的 `datasetId` 回退到数据集报告 Tab。

分析页面仍使用所选报告携带的 `datasetId`，不改变聚合、对比和基线的数据作用域。

## 8. 加载、空状态与错误处理

- 页面和抽屉异步初始化统一使用现有 `Loading`。
- 无可用场景时使用 `Alert` 和“前往场景管理”按钮。
- 无数据集时展示空状态和“前往数据集管理”。
- 无评估器时使用现有提示样式，禁止继续。
- 无有效数据项时禁止最终提交。
- 局部报告加载失败时显示非阻塞提示并保留成功数据。
- 全部报告加载失败时显示错误状态、刷新按钮和可展示错误信息。
- 提交和校验反馈继续使用 `toast`，不使用浏览器原生弹窗。

## 9. 组件边界

建议在现有 `scene-experiments` 模块内拆分：

- 统一页面壳：管理 URL Tab、顶部操作和两类视图切换。
- 项目级报告列表：负责数据集与报告组合、项目级筛选和分页。
- 场景管理视图：从原页面抽取，不改变 CRUD 行为。
- 统一试验抽屉：接收可选的锁定数据集上下文。
- 数据集选择步骤：项目入口使用可搜索单选表格，快捷入口使用只读摘要。
- 执行配置步骤：组合 Webhook 多选和运行参数表单。
- 来源 URL 工具：生成报告详情、聚合、对比和返回地址。

数据集详情只负责传入当前 `projectId`、`datasetId`、有效数据量和提交成功回调，不复制向导状态逻辑。

## 10. 测试与验证

自动化测试覆盖：

- 侧边栏菜单由“场景管理”改为“场景试验”。
- `/scenes` 默认打开“场景试验”Tab，URL Tab 可恢复。
- 场景管理原新增、查询、查看和编辑能力仍可用。
- 项目级报告正确关联数据集，并支持搜索、筛选、排序和分页。
- 部分数据集报告失败时保留成功结果。
- 五步向导的步骤顺序和校验。
- 项目级入口允许搜索并单选数据集。
- 数据集详情入口锁定当前数据集。
- 第四步同时包含 Webhook 选择与运行参数覆盖。
- 两类入口提交成功后的刷新和 Tab 行为。
- 报告详情与分析页面按来源返回。
- 原数据集“试验报告”Tab 仍只展示当前数据集报告。
- 基线、聚合和对比规则不回归。
