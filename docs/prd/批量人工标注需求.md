# 批量人工标注需求

日期：2026-07-07

## 1. 背景与目标

当前人工标注能力已经支持从人工标注任务列表进入单个标注队列，并对队列中的单条数据完成评分、备注、删除、加入数据集等操作。随着业务数据量增长，标注人员每天需要处理约 500-1000 条待标注数据，单条逐项进入和提交的操作路径会成为效率瓶颈。

本需求在“应用评测 -> 人工标注任务列表”中新增“批量标注”入口，为单个人工标注队列提供高效率标注工作台。工作台需要同时覆盖两类典型场景：

- 单条快速标注：用户在一个页面内连续查看待标注数据并快速完成评分，提交后自动切换到下一条待标注数据。
- 批量统一标注：用户通过筛选器选出一批相似待标注数据后，对该批数据统一填写评分和备注，并一次性提交。

本期目标是在保证标注准确率的前提下，通过页面布局、筛选能力、快捷操作、自动流转和批量提交机制，最大限度降低重复操作成本，提高人工标注吞吐量。

## 2. 设计原则

- 快速处理优先：减少页面跳转、弹窗确认、重复选择指标等低价值操作。
- 准确率优先：批量提交前必须让用户明确当前批次范围、命中数量和评分影响，避免误标。
- Langfuse 兼容优先：标注队列、队列数据、评分指标、评分结果继续复用 Langfuse `annotation_queues`、`annotation_queue_items`、`score_configs`、`scores`。
- 不修改 Langfuse 原生表结构：本需求不新增或修改 Langfuse 原生表字段；必要的视图状态、筛选条件优先存储在前端状态或 PA 扩展配置中。
- 队列内闭环：批量标注页面围绕单个标注队列工作，不跨队列批量操作。
- 状态可追踪：所有单条或批量标注提交后，必须正确更新队列数据状态、标注人、完成时间和评分记录。
- 误操作可控：批量操作需要二次确认或明确的提交摘要；提交失败时需要展示失败明细，并支持重试。

## 4. 使用场景

### 4.1 单条快速标注场景

用户进入批量标注工作台后，左侧默认只展示当前队列的待标注数据。用户选择一条数据后，右侧展示该数据的详情、上下文、评分指标和备注输入。提交后系统自动保存评分，将该队列数据状态更新为已完成，并自动选中下一条待标注数据。

该场景适用于每条数据需要独立判断的情况，例如回答质量、事实准确性、工具调用合理性、异常原因归类等。

### 4.2 批量统一标注场景

用户通过高级筛选选择一类相似数据，例如同一错误类型、同一环境、同一标签、同一 metadata 字段、同一业务场景或同一异常模式。筛选命中后，右侧显示批量评分表单，用户对当前批次统一填写评分和备注。提交前系统展示本次影响的数据数量、筛选条件摘要和评分内容。确认后系统对本批待标注数据批量写入 scores，并将成功项更新为已完成。

该场景适用于已确认同一类样本可以使用相同评分结论的情况，例如某一批明显失败的 Trace、同类 badcase、同一模板错误、同一模型输出格式问题等。

## 5. 页面入口与导航

入口位置：

- 一级模块：应用评测。
- 页面：人工标注任务列表。
- 操作区：每个标注任务行新增“批量标注”按钮。

点击规则：

- 点击“批量标注”后进入新页面：`/projects/:projectId/evaluation/manual-annotations/:queueId/batch`。
- 页面标题展示当前标注任务名称。
- 页面需要保留返回人工标注任务列表的入口。

按钮展示规则：

- 队列正常存在时展示“批量标注”入口。
- 队列已删除或无可访问数据时按钮置灰或进入后展示空状态。

## 6. 页面整体布局

批量标注工作台采用左右分栏布局：

| 区域 | 说明 |
| --- | --- |
| 顶部栏 | 展示任务名称、队列进度、当前模式、返回入口、保存状态 |
| 左侧列表区 | 展示队列数据列表、筛选器、状态切换、批次选择 |
| 右侧标注区 | 展示当前数据详情、评分指标、备注、单条或批量提交操作 |

推荐布局比例：

- 左侧列表区宽度约 36%-42%，可收起到窄列表。
- 右侧标注区宽度约 58%-64%，优先保证数据详情和评分表单的可读性。
- 在小屏幕下可切换为上下布局，但仍需保证列表和标注表单之间的快速切换。

页面模式：

| 模式 | 说明 |
| --- | --- |
| 单条标注模式 | 左侧选中一条数据，右侧针对单条数据评分 |
| 批量标注模式 | 左侧基于筛选条件形成批次，右侧针对批次统一评分 |

模式切换规则：

- 默认进入单条标注模式。
- 用户开启“批量标注”开关或点击“按当前筛选批量标注”后进入批量标注模式。
- 批量模式下右侧不绑定单条数据详情，而展示批次摘要、样本预览和统一评分表单。

## 7. 左侧队列数据列表

### 7.1 默认展示

左侧列表默认只展示 `status = PENDING` 的待标注数据，满足连续处理的主路径。

用户可通过状态切换查看：

| 状态视图 | 说明 |
| --- | --- |
| 待标注 | 默认视图，仅展示 `PENDING` |
| 已完成 | 展示 `COMPLETED` |
| 全部 | 展示当前队列全部数据 |

### 7.2 列表字段

| 字段 | 说明 | 数据来源 |
| --- | --- | --- |
| 队列数据 ID | 队列项唯一 ID | `annotation_queue_items.id` |
| 对象类型 | TRACE、OBSERVATION、SESSION | `annotation_queue_items.object_type` |
| 源对象 ID | trace、observation 或 session ID | `annotation_queue_items.object_id` |
| 状态 | PENDING、COMPLETED | `annotation_queue_items.status` |
| 摘要 | 输入、输出或 metadata 中提取的短摘要 | 源对象详情 |
| 标签 | trace tags 或 metadata tags | 源对象详情 |
| 环境 | 环境字段 | trace/environment 或 metadata |
| 创建时间 | 加入队列时间 | `annotation_queue_items.created_at` |
| 完成时间 | 标注完成时间 | `annotation_queue_items.completed_at` |
| 标注人 | 完成人 | `annotation_queue_items.annotator_user_id` |

列表需要支持：

- 分页或虚拟滚动，确保千条级数据流畅展示。
- 当前选中项高亮。
- 已完成项和待标注项视觉区分。
- 单条数据标注完成后列表状态即时更新。
- 支持刷新，但刷新不能丢失当前筛选条件。

### 7.3 列表项摘要

为提升快速判断效率，列表项应尽量展示可扫描信息：

- 优先展示源数据的 `name`、`traceId`、`sessionId`、`userId`、`environment`。
- 输入输出过长时只展示摘要，右侧详情中展示完整内容。
- 如果存在错误信息，列表项展示错误标识和错误摘要。
- 如果存在已有人工评分，展示已评分标识。

## 8. 筛选能力

筛选能力参考 Trace 日志中的高级筛选逻辑，支持字段、操作符和值的组合条件。

### 8.1 基础筛选

| 筛选项 | 说明 |
| --- | --- |
| 状态 | 待标注、已完成、全部 |
| 对象类型 | TRACE、OBSERVATION、SESSION |
| 时间范围 | 加入队列时间、源对象创建时间、完成时间 |
| 关键词 | 支持按源对象 ID、sessionId、userId、摘要内容搜索 |
| 标注人 | 已完成数据可按标注人过滤 |
| 是否已有评分 | 有评分、无评分 |

### 8.2 高级筛选

高级筛选由多个条件组成，每个条件包含：

| 字段 | 说明 |
| --- | --- |
| 字段路径 | 如 `trace.name`、`trace.userId`、`metadata.errorType`、`scores.quality` |
| 操作符 | 等于、不等于、包含、不包含、大于、小于、存在、不存在、区间 |
| 值 | 根据字段类型输入字符串、数字、布尔值、枚举或时间 |
| 关系 | 条件之间支持 AND；OR 可作为增强能力 |

建议首期支持字段：

- `annotation_queue_items.status`
- `annotation_queue_items.object_type`
- `annotation_queue_items.created_at`
- `annotation_queue_items.completed_at`
- `trace.id`
- `trace.name`
- `trace.session_id`
- `trace.user_id`
- `trace.environment`
- `trace.tags`
- `trace.input`
- `trace.output`
- `trace.metadata.*`
- `observation.type`
- `observation.name`
- `observation.input`
- `observation.output`
- `scores.name`
- `scores.value`
- `scores.string_value`

### 8.3 筛选结果与批次

筛选结果需要同时展示：

- 当前筛选命中总数。
- 当前筛选命中的待标注数量。
- 当前筛选命中的已完成数量。
- 批量标注预计影响数量，默认只统计待标注数据。

批量标注模式下，系统默认仅对筛选命中的 `PENDING` 数据提交评分，避免覆盖已完成数据。若后续需要支持覆盖已完成评分，必须单独增加开关和强提示。

## 9. 右侧单条标注区

### 9.1 数据详情展示

单条模式下，右侧上半区展示当前选中数据详情：

| 信息区 | 说明 |
| --- | --- |
| 基础信息 | 对象类型、对象 ID、状态、创建时间、环境、用户标识 |
| 输入 | 源 Trace/Observation/Session 的 input |
| 输出 | 源 Trace/Observation/Session 的 output |
| Metadata | JSON 格式展示，支持折叠和复制 |
| 调用链 | Trace 或 Observation 关联调用链，复用已有 Trace 详情能力 |
| 历史评分 | 当前对象已有 scores，区分人工标注和自动评分 |

数据详情需要支持：

- 输入、输出、metadata 一键复制。
- 长文本折叠和展开。
- JSON 格式化展示。
- 对错误信息、异常状态进行明显提示。

### 9.2 评分表单

评分表单从当前标注队列关联的 `score_configs` 加载，渲染规则沿用人工标注模块：

| 指标类型 | 输入方式 |
| --- | --- |
| NUMERIC | 数值输入或滑块，受 min/max 约束 |
| CATEGORICAL | 单选或下拉 |
| BOOLEAN | 是/否选择 |
| TEXT | 文本输入 |

每个指标支持：

- 填写评分值。
- 填写备注。
- 查看指标描述。
- 展示必填/选填状态。

### 9.3 提交与自动下一条

单条提交规则：

- 点击“保存并下一条”后，系统写入或更新该对象对应的 `scores`。
- 成功后将当前 `annotation_queue_items.status` 更新为 `COMPLETED`。
- 写入 `annotator_user_id` 和 `completed_at`。
- 自动选择当前筛选结果中的下一条待标注数据。
- 如果已没有下一条待标注数据，展示“当前筛选条件下已全部完成”。

自动下一条选择规则：

1. 优先选择当前列表中当前位置之后的下一条 `PENDING` 数据。
2. 若当前页没有下一条，自动加载下一页。
3. 若筛选结果中没有待标注数据，提示用户切换筛选条件或返回任务列表。

保存动作：

| 操作 | 说明 |
| --- | --- |
| 保存 | 保存当前评分，不自动跳转 |
| 保存并下一条 | 保存后自动切换下一条待标注数据 |
| 跳过 | 不修改状态，切换到下一条待标注数据 |
| 标记无法判断 | 可作为特殊评分值或备注写入，具体取决于 score config 配置 |

## 10. 右侧批量标注区

### 10.1 批次形成

批量模式下，批次来源为当前筛选条件命中的待标注数据。

批次范围规则：

- 默认仅包含 `status = PENDING` 的队列数据。
- 批次必须归属于当前 `queue_id`。
- 批次提交前重新计算命中数量，避免筛选后数据状态已变化。

### 10.2 批次预览

批量提交前，右侧需要展示：

| 信息 | 说明 |
| --- | --- |
| 筛选条件摘要 | 展示本批次由哪些条件命中 |
| 待标注命中数量 | 本次实际会提交的 PENDING 数据数量 |
| 样本预览 | 展示前若干条命中数据摘要 |
| 评分内容 | 展示本次统一写入的评分值和备注 |
| 风险提示 | 明确提示该操作会对当前批次统一打标 |

如果命中数量为 0，不允许提交。

### 10.3 批量评分表单

批量评分表单同样根据 `score_configs` 渲染。用户可选择本次要批量写入的指标。

规则：

- 未勾选的指标不写入。
- 已勾选的指标必须填写合法评分值。
- 每个指标可填写统一备注。
- 支持“一键应用到本批次”。
- 支持提交前检查：至少选择一个指标，且至少命中一条待标注数据。

### 10.4 批量提交

批量提交规则：

- 系统对本批次每条待标注数据写入对应 `scores`。
- 每条数据的 score `source` 固定为 `ANNOTATION`。
- `author_user_id` 写入当前用户。
- 对成功写入评分的数据，将队列项状态更新为 `COMPLETED`。
- 批量提交操作需要返回成功数、失败数和失败原因。

部分失败处理：

- 成功项保持已完成，不回滚。
- 失败项保持待标注。
- 页面展示失败明细，支持按失败项重新筛选或重试。
- 如果失败原因是并发状态变化，例如已被他人完成，应提示该项已跳过。

### 10.5 提交后进入下一批

批量提交成功后，系统自动刷新当前筛选条件：

- 若仍有符合条件的待标注数据，展示下一批批次摘要。
- 若当前筛选条件下已无待标注数据，提示“当前批次已全部完成”，并引导用户调整筛选条件。
- 若用户开启“自动进入下一批”，提交成功后焦点停留在批量评分表单，方便连续处理。

## 11. 高效标注能力

### 11.1 快捷键

建议支持快捷键：

| 快捷键 | 动作 |
| --- | --- |
| `J` / `K` | 下一条 / 上一条 |
| `Enter` 或 `Cmd/Ctrl + Enter` | 保存并下一条 |
| `S` | 保存 |
| `F` | 聚焦筛选器 |
| `B` | 切换批量标注模式 |
| `1`-`9` | 快速选择分类或评分档位 |
| `Esc` | 退出编辑焦点或关闭二级浮层 |

快捷键必须避免和输入框冲突。当焦点在文本输入、备注、JSON 搜索框中时，不触发全局快捷键。

### 11.2 默认值与记忆

为减少重复操作，页面可支持：

- 记忆用户最近一次使用的筛选条件。
- 记忆用户最近一次选择的状态视图。
- 记忆用户最近一次使用的标注模式。
- 在同一队列内保存临时草稿，页面刷新后可恢复未提交评分。

本期如不实现持久化记忆，至少需要保证页面内切换数据时不丢失当前筛选条件。

### 11.3 标注准确率辅助

为兼顾效率和准确率，页面需要提供：

- 指标说明随时可见。
- 当前数据和历史评分并排参考。
- 批量提交前展示样本预览。
- 已完成数据默认不参与批量提交。
- 对超大批次增加确认提示，例如超过 100 条时要求用户再次确认。

## 12. 数据模型与写入规则

本需求继续复用现有人工标注模块的数据模型。

### 12.1 annotation_queues

用于表示人工标注任务。本页面根据 `queue_id` 加载任务名称、描述、评分指标配置和队列统计。

### 12.2 annotation_queue_items

用于表示队列中的标注数据。批量标注页面查询、筛选、状态更新都围绕该表进行。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 队列数据 ID |
| `queue_id` | 所属标注队列 |
| `object_id` | 源对象 ID |
| `object_type` | TRACE、OBSERVATION、SESSION |
| `status` | PENDING、COMPLETED |
| `annotator_user_id` | 完成标注人 |
| `completed_at` | 完成时间 |
| `project_id` | 项目 ID |

### 12.3 score_configs

用于生成标注评分表单。批量页面必须使用当前队列关联的 `score_config_ids`，不得让用户在提交时临时新增队列外指标。

### 12.4 scores

用于保存单条或批量人工标注结果。

写入规则：

- `project_id`：当前项目。
- `trace_id` / `observation_id`：根据标注对象类型和源对象关系写入。
- `name`：评分指标名称。
- `config_id`：评分指标 ID。
- `data_type`：评分指标类型。
- `value` / `string_value`：根据指标类型写入。
- `comment`：标注备注。
- `source`：固定为 `ANNOTATION`。
- `author_user_id`：当前用户。

更新规则：

- 对同一对象、同一 `config_id`、同一 `source = ANNOTATION` 的既有评分，优先更新而不是重复创建。
- 如 Langfuse 原生语义允许多次评分记录，则需要在接口层统一返回最新人工评分，避免列表显示混乱。

## 13. 接口需求

### 13.1 查询批量标注页面初始化数据

用途：进入页面时加载队列信息、评分指标、统计数据和默认列表。

返回内容：

- 标注队列基础信息。
- 队列统计：总量、待标注、已完成、完成率。
- 队列关联评分指标。
- 默认列表数据。

### 13.2 查询队列数据列表

用途：左侧列表分页查询。

请求参数：

- `queueId`
- `projectId`
- `status`
- `objectType`
- `keyword`
- `timeRange`
- `advancedFilters`
- `page`
- `pageSize`
- `sort`

返回内容：

- 数据列表。
- 分页信息。
- 当前筛选命中统计。

### 13.3 查询单条队列数据详情

用途：右侧单条标注详情展示。

请求参数：

- `queueItemId`

返回内容：

- 队列数据基础信息。
- 源对象详情。
- 输入、输出、metadata。
- 调用链信息。
- 历史评分。

### 13.4 单条保存评分

用途：保存当前队列数据的人工评分。

请求内容：

- `queueItemId`
- `scores[]`
- `complete`

处理规则：

- 校验队列数据状态。
- 校验评分值合法性。
- 写入或更新 scores。
- 当 `complete = true` 时更新队列项为 `COMPLETED`。

### 13.5 批量保存评分

用途：对当前筛选命中的待标注数据批量写入评分。

请求内容：

- `queueId`
- `filters`
- `scorePayloads[]`
- `expectedPendingCount`
- `confirmLargeBatch`

处理规则：

- 服务端必须重新按 filters 查询待标注数据。
- 如果实际命中数量和 `expectedPendingCount` 差异较大，需要返回确认提示。
- 对每条命中数据写入或更新 scores。
- 成功项更新为 `COMPLETED`。
- 返回成功数、失败数和失败明细。

### 13.6 批量预览

用途：批量提交前预览当前筛选条件命中的数据范围。

请求内容：

- `queueId`
- `filters`
- `limit`

返回内容：

- 命中总数。
- 待标注命中数。
- 已完成命中数。
- 样本预览列表。
- 筛选条件摘要。

## 14. 并发控制

并发规则：

- 提交前服务端重新读取队列项状态。
- 已被他人完成的数据不再重复提交，返回跳过原因。
- 单条模式可沿用 Langfuse 锁定机制；锁定失败时提示用户当前数据正在被其他人处理。
- 批量模式不长时间锁定全部数据，提交时以状态校验为准。

## 15. 状态与异常处理

| 场景 | 处理方式 |
| --- | --- |
| 队列不存在 | 提示任务不存在或已删除，返回列表 |
| 筛选无结果 | 展示空状态，引导修改筛选条件 |
| 当前筛选下无待标注数据 | 提示已全部完成 |
| 单条保存失败 | 保留当前表单内容，展示失败原因 |
| 批量部分失败 | 展示成功数、失败数、失败明细 |
| 评分配置已归档 | 历史值可展示，不允许新增空白评分项 |
| 网络中断 | 保留页面内草稿，允许重试 |
| 页面刷新 | 恢复队列、筛选和当前模式；未提交数据不保证持久恢复 |

## 16. 统计与进度

页面顶部展示当前队列核心进度：

| 指标 | 说明 |
| --- | --- |
| 队列总量 | 当前队列全部数据量 |
| 待标注 | `PENDING` 数量 |
| 已完成 | `COMPLETED` 数量 |
| 完成率 | 已完成 / 总量 |
| 当前筛选命中 | 当前筛选条件下的数据量 |
| 本次批量影响 | 批量模式下将提交的待标注数量 |

统计数据需要在单条保存、批量保存、筛选变化后刷新。

## 17. 验收标准

### 17.1 入口与页面

- 在“应用评测 -> 人工标注任务列表”中，每个任务行展示“批量标注”按钮。
- 点击按钮进入批量标注工作台新页面。
- 页面能正确展示当前标注队列名称、进度和评分指标。

### 17.2 单条快速标注

- 左侧默认只展示待标注数据。
- 用户可切换查看已完成和全部数据。
- 点击左侧任意数据，右侧展示该数据详情和评分表单。
- 用户提交单条评分后，该数据状态变为已完成。
- 提交成功后自动选中下一条待标注数据。

### 17.3 筛选与批量标注

- 页面支持基础筛选和高级筛选。
- 高级筛选能力与 Trace 日志高级筛选的字段组合交互保持一致。
- 用户可基于当前筛选结果进入批量标注模式。
- 批量提交前展示命中数量、筛选条件摘要和样本预览。
- 批量提交后成功项写入 scores，并更新为已完成。
- 批量提交后自动刷新并进入下一批符合条件的待标注数据。

### 17.4 可靠性

- 已完成数据默认不被批量提交覆盖。
- 部分失败时成功项保留，失败项保持待标注，并展示失败原因。
- 服务端按提交时最新筛选结果和状态执行，避免前端缓存导致误标。

## 18. 指标与效果评估

上线后建议关注：

| 指标 | 目标 |
| --- | --- |
| 人均每日完成标注量 | 支持 500-1000 条/人/天 |
| 单条标注平均操作耗时 | 相比原单条页面明显降低 |
| 批量提交成功率 | 高于 99% |
| 批量误标反馈率 | 可追踪且持续下降 |
| 筛选命中后批量完成占比 | 衡量批量模式使用价值 |

- 支持按照业务标签自动推荐下一批待标注数据。
