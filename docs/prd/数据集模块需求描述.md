# 数据集管理需求设计

日期：2026-07-03

## 1. 背景与目标

本需求面向数据集管理能力建设，参考 Langfuse 社区版的数据集实现，要求数据结构依赖的核心表与 Langfuse 保持一致。本期目标是完成数据集与数据项的基础管理闭环：新建、查询、修改元信息、进入详情、导入导出、查看和维护单条数据。

本期不实现 Langfuse 的实验运行管理能力。`dataset_runs` 与 `dataset_run_items` 作为兼容关系保留在数据模型说明中，但页面不提供新增实验运行、删除实验运行、运行对比等功能。

## 2. 设计原则

- Langfuse 兼容优先：复用 Langfuse 社区版核心表结构，不为数据集类型新增主表字段。
- 轻扩展：业务类型写入 `datasets.metadata.type`，在查询、统计、展示层读取和约束。
- 数据项字段对齐 Langfuse：单条数据围绕 `input`、`expected_output`、`metadata`、`status`、source 信息维护。
- 导入导出对称：导出的 CSV/JSONL 能再次导入，尽量不丢失数据项核心字段。
- 本期聚焦可用闭环：先完成数据集和数据项管理，不扩展实验运行闭环。

## 3. 数据模型

### 3.1 datasets

`datasets` 保存数据集元信息，字段参考 Langfuse 社区版：

| 字段 | 说明 |
| --- | --- |
| `id` | 数据集 ID |
| `project_id` | 项目 ID |
| `name` | 数据集名称，项目内唯一 |
| `description` | 数据集描述 |
| `metadata` | 数据集自定义元信息，业务类型写入此字段 |
| `remote_experiment_url` | Langfuse 远程实验兼容字段，本期不使用 |
| `remote_experiment_payload` | Langfuse 远程实验兼容字段，本期不使用 |
| `remote_experiment_enabled` | Langfuse 远程实验兼容字段，本期不使用 |
| `input_schema` | 数据项 `input` 的 JSON Schema |
| `expected_output_schema` | 数据项 `expected_output` 的 JSON Schema |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

数据集类型不新增表字段，统一写入 `metadata.type`。类型枚举：

| 展示名 | 存储建议值 | 说明 |
| --- | --- | --- |
| 评测集 | `evaluation` | 用于评测任务的数据集 |
| badcase集 | `badcase` | 用于收集和分析 badcase |
| 黄金级 | `golden` | 高质量基准数据集 |
| 异常集 | `anomaly` | 异常样本或异常场景集合 |

当用户编辑 metadata 时，系统必须保护 `metadata.type` 不被意外删除或写成非法枚举。

### 3.2 dataset_items

`dataset_items` 保存数据集中的单条数据，字段参考 Langfuse 社区版：

| 字段 | 说明 |
| --- | --- |
| `id` | 数据项 ID |
| `project_id` | 项目 ID |
| `status` | 数据项状态，`ACTIVE` 或 `ARCHIVED` |
| `input` | 输入数据，JSON |
| `expected_output` | 期望输出，JSON |
| `metadata` | 数据项元信息，JSON |
| `source_trace_id` | 来源 trace ID |
| `source_observation_id` | 来源 observation ID |
| `dataset_id` | 所属数据集 ID |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `valid_from` | 版本生效开始时间 |
| `valid_to` | 版本生效结束时间 |
| `is_deleted` | 是否删除 |

单条数据的查看、修改、保存、删除都围绕 `dataset_items` 实现。删除采用 Langfuse 的版本化/软删除语义：优先设置当前版本的 `valid_to` 或 `is_deleted`，避免破坏历史版本和与 run item 的兼容关系。

### 3.3 dataset_item_media

`dataset_item_media` 保留为媒体引用兼容能力。当数据项的 `input`、`expected_output`、`metadata` 中包含图片、音频等媒体引用时，可按 Langfuse 结构记录引用关系。

本期需求只要求兼容说明，不强制实现媒体上传和媒体管理 UI。

### 3.4 dataset_runs 与 dataset_run_items

`dataset_runs` 与 `dataset_run_items` 保留为 Langfuse 实验运行相关兼容表：

- `dataset_runs` 记录某个数据集的一次运行或实验。
- `dataset_run_items` 记录运行和数据项、trace、observation 的关联。

本期不提供实验运行管理页面，不提供新增、删除、对比运行结果等功能。数据集列表和详情中可以显示运行数量等只读统计，但不进入完整 run 管理闭环。

### 3.5 metadata 约定

为了保持表结构与 Langfuse 一致，本期新增业务信息优先写入原有 JSON 字段，不新增扩展表。

`datasets.metadata` 约定字段：

| 字段 | 说明 |
| --- | --- |
| `type` | 数据集类型，必填 |
| `ops.lastImportAt` | 最近一次导入完成时间，导入成功后更新 |
| `ops.lastExportAt` | 最近一次导出时间，导出成功后可更新 |

`dataset_items.metadata` 可选约定字段：

| 字段 | 说明 |
| --- | --- |
| `category` | badcase 或评测分类 |
| `priority` | 优先级，如 `high`、`medium`、`low` |
| `tags` | 标签数组 |
| `anomalyType` | 异常类型 |
| `importBatchId` | 导入批次 ID |
| `importedAt` | 数据项导入时间 |

这些字段是产品统计约定，不改变 Langfuse 表结构。用户自定义 metadata 仍可保留，但系统字段需要避免被非法覆盖。

## 4. 功能需求

### 4.1 数据集列表

数据集列表页支持：

- 新建数据集。
- 查询数据集。
- 修改数据集元信息。
- 进入数据集详情。
- 导入数据集。
- 导出数据集。

列表字段参考 Langfuse，并加入类型展示：

| 字段 | 来源 |
| --- | --- |
| 名称 | `datasets.name` |
| 描述 | `datasets.description` |
| 类型 | `datasets.metadata.type` |
| 数据量 | `dataset_items` 聚合 |
| 实验运行数 | `dataset_runs` 聚合，只读 |
| 创建时间 | `datasets.created_at` |
| 更新时间 | `datasets.updated_at` |
| Metadata | `datasets.metadata` |
| Input Schema | `datasets.input_schema` |
| Expected Output Schema | `datasets.expected_output_schema` |
| 操作 | 编辑、进入、导入、导出 |

查询能力：

- 按名称模糊查询。
- 按类型筛选。
- 按创建时间或更新时间范围筛选。
- 按数据项状态聚合筛选可作为增强能力。

### 4.2 新建数据集

新建表单参考 Langfuse 的 Dataset Form，并增加“数据集类型”必填项。

字段：

- 名称：必填，项目内唯一，允许使用 `/` 表达目录层级。
- 类型：必填，支持评测集、badcase集、黄金级、异常集。
- 描述：选填。
- Metadata：选填，合法 JSON 对象或 JSON 值。
- Input Schema：选填，合法 JSON Schema。
- Expected Output Schema：选填，合法 JSON Schema。

保存规则：

- 类型写入 `metadata.type`。
- 用户输入的 metadata 与系统类型合并。
- 若用户 metadata 中已有 `type`，以表单选择的类型为准。
- 名称重复时阻止创建。
- schema 非法时阻止创建。
- 创建成功后进入数据集详情页。

### 4.3 修改数据集元信息

可修改字段：

- 名称。
- 类型。
- 描述。
- Metadata。
- Input Schema。
- Expected Output Schema。

更新规则：

- 修改类型时更新 `metadata.type`。
- 修改 metadata 时不能丢失合法的 `metadata.type`。
- 修改 schema 时需要校验已有 ACTIVE 数据项是否仍符合 schema。
- 如果已有数据项不符合新 schema，阻止保存并返回错误明细，包括数据项 ID、字段、路径和错误原因。

### 4.4 数据集详情

进入数据集后，页面上方展示数据集元信息和统计信息，主体展示数据项表格。

基础统计所有类型都展示：

- 总数据量。
- ACTIVE 数量。
- ARCHIVED 数量。
- 最近更新时间。
- 最近导入时间，优先读取 `datasets.metadata.ops.lastImportAt`。
- 最近导出时间可作为增强能力，优先读取 `datasets.metadata.ops.lastExportAt`。

类型专属统计：

| 类型 | 统计项 |
| --- | --- |
| 评测集 | 期望输出完整率、input schema 通过率、expected output schema 通过率 |
| badcase集 | 问题分类分布、待处理数量、高优先级数量 |
| 黄金级 | 有效样本数、覆盖标签数、schema 通过率 |
| 异常集 | 异常类型分布、高优先级数量、最近新增异常数 |

类型专属统计优先从数据项 `metadata` 中读取约定字段，例如 `category`、`priority`、`tags`、`anomalyType`。如果字段不存在，统计卡片展示空状态，而不是报错。

### 4.5 数据项表格

数据项表格字段参考 Langfuse：

| 字段 | 来源 |
| --- | --- |
| Item ID | `dataset_items.id` |
| Source | `source_trace_id` / `source_observation_id` |
| Status | `dataset_items.status` |
| Created At | `dataset_items.created_at` |
| Input | `dataset_items.input` |
| Expected Output | `dataset_items.expected_output` |
| Metadata | `dataset_items.metadata` |
| Actions | 查看、编辑、保存、删除 |

表格能力：

- 分页。
- 按 ID 查询。
- 全文查询 `input`、`expected_output`、`metadata` 可作为增强能力。
- 按 status 筛选。
- 调整行高或展开 JSON 可作为增强能力。

### 4.6 单条数据操作

单条数据支持：

- 查看详情：展示完整 `input`、`expected_output`、`metadata`、source 信息、创建更新时间。
- 编辑：可修改 `status`、`input`、`expected_output`、`metadata`、source 信息。
- 保存：保存前校验 JSON 合法性和 schema 约束。
- 删除：二次确认后执行软删除或版本化删除。

保存规则：

- `input` 必须符合数据集的 `input_schema`，若 schema 存在。
- `expected_output` 必须符合数据集的 `expected_output_schema`，若 schema 存在。
- `metadata` 必须是合法 JSON。
- 保存成功后刷新统计和表格。

## 5. 导入导出

### 5.1 导入格式

支持 CSV 和 JSONL。

CSV 导入流程：

1. 上传 CSV 文件。
2. 解析并展示预览。
3. 用户配置字段映射。
4. 系统将列映射到 `input`、`expectedOutput`、`metadata`。
5. 执行预校验。
6. 校验通过后写入 `dataset_items`。

CSV 映射规则参考 Langfuse：

- 单列可映射为原始 JSON 值，也可包装为对象。
- 多列映射为对象。
- 支持将多列映射到 schema key。
- 空字符串或 `null` 解析为 JSON null。
- 字符串、数字、布尔、对象、数组应尽量按 JSON 语义解析。

JSONL 导入规则：

- 每行是一条数据项。
- 每行可包含：`id`、`status`、`input`、`expectedOutput`、`metadata`、`sourceTraceId`、`sourceObservationId`。
- 缺失 `status` 时默认 `ACTIVE`。
- `expectedOutput` 映射到数据库字段 `expected_output`。

导入校验：

- 文件不能为空。
- 文件大小限制需在实现中明确，建议默认 10MB，可配置。
- CSV 必须至少包含一列表头。
- JSONL 每行必须是合法 JSON 对象。
- 如果数据集配置了 schema，每条数据写入前必须校验。
- 校验失败时返回行号、字段、JSON path、错误原因。

执行策略：

- 优先采用“预校验 + 执行”两阶段。
- 尽量避免半成功状态。
- 如果后端无法完全事务化，需要返回成功数、失败数和失败明细。

### 5.2 导出格式

支持数据集级导出和数据项级导出。

数据集级导出：

- 包含数据集元信息。
- 包含所有数据项。
- JSONL 可作为完整备份格式。

数据项级导出：

- 只导出当前筛选条件下的数据项。
- 支持 CSV 和 JSONL。

导出字段：

- `id`
- `status`
- `input`
- `expectedOutput`
- `metadata`
- `sourceTraceId`
- `sourceObservationId`
- `createdAt`
- `updatedAt`

CSV 导出适合人工编辑。JSONL 导出适合备份、迁移和程序处理。导出字段与导入字段保持对称，保证导出后再导入不会丢失核心数据。

## 6. 错误处理

需要明确提示的错误：

- 数据集名称重复。
- 数据集类型缺失或非法。
- Metadata 不是合法 JSON。
- JSON Schema 非法。
- 已有数据项不符合新 schema。
- 单条数据 JSON 非法。
- 单条数据不符合 schema。
- 导入文件为空。
- 导入文件超限。
- 导入文件格式错误。
- CSV 无表头或无有效列。
- JSONL 某行不是合法 JSON 对象。
- 批量导入部分失败。
- 单条保存冲突。
- 删除操作需要二次确认。

错误提示应尽量包含用户可修复的信息，例如字段名、行号、数据项 ID、JSON path 和错误原因。

## 7. 权限与审计

权限建议参考 Langfuse 的读写边界：

- 读权限：查看数据集列表、详情、数据项、导出。
- 写权限：新建、修改、导入、保存数据项、删除数据项。

审计建议记录：

- 创建数据集。
- 修改数据集元信息。
- 导入数据项。
- 导出数据项。
- 修改单条数据项。
- 删除单条数据项。

## 8. 非目标

本期不包含：

- 实验运行创建、删除、对比。
- run item 详情分析。
- 自动评测任务编排。
- 媒体上传 UI。
- 统计缓存表或扩展表。
- 对 Langfuse 主表结构进行破坏性变更。

## 9. 验收标准

- 可以创建四种类型的数据集：评测集、badcase集、黄金级、异常集。
- 数据集类型存储在 `datasets.metadata.type`，不新增 `datasets.type` 字段。
- 可以按名称和类型查询数据集。
- 可以修改数据集元信息，并且不会意外丢失 `metadata.type`。
- 可以进入数据集详情页，看到基础统计和类型专属统计。
- 可以查看数据集中的所有数据项详情。
- 可以对单条数据项执行查看、修改、保存、删除。
- 保存数据项时会校验 JSON 合法性和 schema 约束。
- 可以导入 CSV 和 JSONL。
- 可以导出 CSV 和 JSONL。
- 导出后的 JSONL 能再次导入，且不丢失核心字段。
- 数据结构依赖的核心表与 Langfuse 社区版保持一致。
