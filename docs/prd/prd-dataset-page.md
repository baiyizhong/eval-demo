## 1. 产品概述

### 1.1 功能定位

数据集管理是 AEP 平台评测体系的基础设施模块，用于创建、管理、维护 AI Agent 评测所需的标注数据集。数据集是连接 Trace 观测数据与评测/标注流程的核心纽带：用户可以将 Trace 转化为数据集条目，也可以通过文件导入批量构建数据集，最终用于 LLM 自动评测或人工标注任务。

### 1.2 用户角色

| 角色 | 描述 | 核心场景 |
|------|------|----------|
| 算法工程师 | 开发调优 AI Agent，准备评测数据 | 创建数据集、从 Trace 导入数据、导出数据集、管理数据版本 |
| 标注人员 | 负责人工标注和评估 | 浏览数据集条目、查看输入输出、参与标注 |
| 项目经理 | 项目管理和质量监控 | 查看数据集概况、按类别检索、关注 BadCase 数据集 |

### 1.3 入口位置

- 左侧导航栏「评测」→「数据集」
- 路由: `/project/[id]/evaluations/datasets`

### 1.4 数据集在系统中的角色

```
                    ┌──────────────┐
                    │  Trace 日志   │
                    └──────┬───────┘
                           │ 加入数据集 (F-2.5)
                           ▼
┌───────────┐     ┌──────────────┐     ┌────────────────┐
│ 文件导入   │────▶│   数据集      │────▶│  LLM 自动评测   │
│ CSV/JSON  │     │  (Datasets)  │     │  (Eval Tasks)  │
└───────────┘     └──────┬───────┘     └────────────────┘
                         │
                         │ 发起标注
                         ▼
                  ┌──────────────┐
                  │  人工标注     │
                  │ (Annotation)  │
                  └──────────────┘
```

**分类定义**:

| 分类 | 标签值 | 徽章颜色 | 含义 |
|------|--------|----------|------|
| 评测数据集 | `evaluation` | 蓝色 | 用于 LLM 自动评测的标准评测集 |
| BadCase 数据集 | `badcase` | 红色 | 评估中发现的低质量样本集合 |
| Golden 数据集 | `golden` | 黄色/金色 | 高质量标准答案的黄金评测集 |
| 异常数据集 | `anomaly` | 橙色 | 异常/边界案例集合 |

**特殊规则**: 被标记为 `evaluation` 标签的数据集，反过来归类为"通用数据集"（`general`），区别于手动选择的特定评测类数据集。

#### 2.1.3 数据集表格

| 列名 | 数据源 | 渲染方式 |
|------|--------|----------|
| 名称 | `dataset.name` | 链接文本，点击跳转详情页 |
| 描述 | `dataset.description` | 截断文本（过长省略），无数据时显示「-」 |
| 类型 | `dataset.tags → category` | 彩色徽章（蓝/红/金/橙） |
| 样本数 | `dataset.item_count` | 数字徽章 |
| 创建时间 | `dataset.created_at` | zh-CN 格式化日期 |
| 操作 | - | 编辑按钮、导出按钮、删除按钮 |

#### 2.1.4 数据集 CRUD

| 编号 | 操作 | 描述 | 触发方式 |
|------|------|------|----------|
| F-2.1.4a | 创建 | 弹出创建弹窗，填写名称/分类/描述/元数据 | 页面顶部「创建数据集」按钮 |
| F-2.1.4b | 编辑 | 弹出编辑弹窗，修改名称/描述/元数据 | 表格行末「编辑」按钮 |
| F-2.1.4c | 删除 | 弹出确认对话框，警告为不可逆操作 | 表格行末「删除」按钮 |
| F-2.1.4d | 导出 | 以 JSON 文件下载数据集到本地 | 表格行末「导出」按钮 |

**创建/编辑弹窗字段**:

| 字段 | 类型 | 校验规则 |
|------|------|----------|
| 名称 | 文本输入 | 必填，最大 100 字符，同项目内唯一 |
| 分类 | 卡片选择器 | 4 类（评测/BadCase/Golden/异常），3 列网格布局，必选 |
| 描述 | 文本域 | 选填，最大 500 字符 |
| 元数据 | 键值对编辑器 | 选填，支持快速模板填充，自动查重键名 |

**删除行为**: 软删除（将数据集内所有条目状态设为 `ARCHIVED`，移除 PA 标签，记录到 `_pa_deleted_datasets`）

#### 2.2.6 数据条目详情抽屉 (DataItemDrawer)

| 区域 | 内容 |
|------|------|
| 头部 | 条目 ID、关闭按钮 |
| 基础信息区 | ID、状态（绿色/灰色徽章）、创建时间、来源 Trace ID（带链接图标） |
| 版本历史入口 | 点击跳转版本历史侧边抽屉 |
| Input 区 | JSON 代码块展示（只读模式）/ JSON 编辑文本框（编辑模式） |
| Expected Output 区 | 同上 |
| Metadata 区 | 同上 |
| 操作按钮 | 复制按钮（每个 JSON 区域）、保存按钮（编辑模式） |

**编辑模式行为**:
- 切换至编辑模式后，三个区域变为可编辑的 textarea
- 失焦时自动校验 JSON 格式，合法则保留，不合法则标红提示
- 保存时调用 API 更新条目（创建新版本）

#### 2.2.7 版本历史

| 编号 | F-2.2.7 |
|------|----------|
| 描述 | 侧边抽屉展示数据条目的版本变更记录 |
| 布局 | 左栏版本列表 + 右栏版本详情 |
| 版本信息 | 版本号、状态（当前版本/历史版本）、生效时间（valid_from） |
| 详情展示 | 选中版本的完整 ID、状态、valid_from、valid_to、Input、Expected Output |
| 数据来源 | 通过 `metadata.original_item_id` 关联同一数据条目的多个版本 |

**版本机制**: 编辑数据条目时不直接修改原行，而是将旧条目的 `valid_to` 设为当前时间，插入一条新行（新 UUID），在新行的 metadata 中记录 `original_item_id` 指向原始条目。版本历史通过查询相同 `original_item_id` 的所有记录汇总得到。

#### 2.2.8 归档确认弹窗

| 元素 | 说明 |
|------|------|
| 标题 | 确认归档 |
| 图标 | 橙色警告图标 |
| 文案 | 提示用户归档后可在历史记录中恢复 |
| 按钮 | 取消（灰色）/ 确认归档（橙色） |

### 2.3 数据导入

#### 2.3.1 导入模态框

| 编号 | F-2.3.1 |
|------|----------|
| 触发方式 | 数据集详情页「导入」按钮 |
| 展示形式 | 模态弹窗 |

**功能**:
- 支持拖拽上传或点击选择文件
- 接受格式: `.csv`、`.json`、`.ndjson`
- 文件大小限制提示
- 下载模板链接: `/dataset-template.csv`
- 导入成功后显示成功条目数
- 导入出错时显示错误详情（具体行/字段），对话框不自动关闭以便用户查看

**模板格式** (CSV):

| 列名 | 描述 |
|------|------|
| `input` | JSON 编码的消息数组，如 `[{"role":"user","content":"..."}]` |
| `expected_output` | JSON 编码的期望输出 |
| `metadata` | JSON 编码的元数据对象 |

#### 2.3.2 导入处理逻辑

| 格式 | 处理方式 |
|------|----------|
| CSV | 逐行解析，每行创建一条数据条目 |
| JSON | 期望为对象数组，遍历创建条目 |
| NDJSON | 逐行解析 JSON，每行创建一条数据条目 |

## 4. API 接口

### 4.1 数据集 CRUD

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | `/api/v2/datasets?project_id={id}&tag={tag?}` | 列出数据集（按可选 tag 过滤，tag=evaluation 特殊处理返回零标签集） |
| POST | `/api/v2/datasets` | 创建数据集（含标签） |
| PATCH | `/api/v2/datasets/{dataset_id}` | 更新名称/描述/元数据 |
| DELETE | `/api/v2/datasets/{dataset_id}` | 软删除（归档所有条目 + 记录删除） |

### 4.2 数据集条目 CRUD

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | `/api/v2/datasets/{dataset_id}/items?page=&limit=&search=&status=` | 分页列表（搜索/状态筛选） |
| POST | `/api/v2/datasets/{dataset_id}/items` | 创建条目 |
| PATCH | `/api/v2/datasets/{dataset_id}/items/{item_id}` | 更新条目（创建新版本） |

### 4.3 导入导出

| 方法 | 路径 | 描述 |
|------|------|------|

**导入请求**: `multipart/form-data`，字段 `file`（文件）

**导出响应 (JSON)**:
```json

  "format": "json",
  "data": [{...}, ...],
  "total": 100
}
```

### 4.4 标签管理

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/v2/datasets/{dataset_id}/tags` | 添加标签（重复返回 409） |

### 4.5 版本历史

| 方法 | 路径 | 描述 |
|------|------|------|

### 4.6 跨模块 Trace → 数据集 API

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/pipeline/traces/{trace_id}/dataset-items` | 单条 Trace 转为数据集条目 |
| POST | `/api/pipeline/traces/batch/dataset-items` | 批量 Trace 转为数据集条目 |

**请求体** (单条):
```json
{
  "dataset_name": "my_dataset",
  "dataset_description": "optional",
  "create_dataset_if_missing": true,
  "input": {"messages": [...]},
  "expected_output": {"answer": "..."},
  "metadata": {"source": "trace"},
  "id": "optional-custom-item-id"
}
```

**请求体** (批量):
```json
{
  "trace_ids": ["trace-id-1", "trace-id-2"],
  "dataset_name": "my_dataset",
  "dataset_description": "optional",
  "create_dataset_if_missing": true
}
```

## 5. 用户交互流程

### 5.1 主流程：创建和管理数据集

```
进入数据集列表 → 查看统计卡片 → 创建新数据集 →
填写名称/分类/描述/元数据 → 提交 →
进入数据集详情 → 导入数据（CSV/JSON） →
浏览条目列表 → 搜索/筛选 → 编辑/归档条目 →
导出数据集
```

### 5.2 子流程：从 Trace 构建数据集

```

```

提交评测任务 → 评测运行器遍历数据集条目 →

### 5.4 子流程：数据条目版本管理

```

修改 Input/Expected Output → 失焦校验 JSON →
点击保存 → 后端创建新版本（valid_to 标记旧版本）→

```

## 8. 技术架构

### 8.1 数据流

```
┌────────────────────────────────────────────┐
│                 前端 (Next.js 14)            │
│  DatasetsPage / DatasetDetailPage           │
│  DataItemDrawer / VersionHistory            │
└──────────────────┬─────────────────────────┘
                   │ REST API (JSON)
┌──────────────────▼─────────────────────────┐
│             后端 (FastAPI)                   │
│  /api/v2/datasets/*                         │
│  /api/pipeline/traces/*/dataset-items       │
└──────┬──────────────────┬──────────────────┘
       │ SQLAlchemy       │ httpx (HTTP)
┌──────▼──────────┐  ┌───▼───────────────────┐
│  PostgreSQL      │  │  Langfuse API         │
│  _pa_dataset_tags│  │  /api/public/datasets │
│  _pa_deleted_    │  │  /api/public/dataset- │
│  datasets        │  │  items                │
│  _pa_eval_tasks  │  │                       │
└─────────────────┘  └───────────────────────┘
```

### 8.2 存储策略

- **Langfuse 原生表** (`datasets`, `dataset_items`): 核心数据存储，由 Langfuse Prisma 管理，PA 后端只读/透传
- **PA 扩展表** (`_pa_dataset_tags`, `_pa_deleted_datasets`): PA 特有元数据，由 SQLAlchemy + Alembic 管理
- **版本控制**: 利用 Langfuse 原生的 `valid_from`/`valid_to` 机制，不额外建表

### 8.3 关键设计决策

| 决策 | 说明 |
|------|------|
| 标签 vs 字段 | 数据集分类以标签（tags）形式存储而非独立字段，保持与 Langfuse 兼容性同时支持多标签 |
| 软删除 | 数据集不物理删除，通过 ARCHIVED 状态 + `_pa_deleted_datasets` 表实现可恢复的软删除 |
| 透传架构 | 数据集核心 CRUD 透传至 Langfuse，PA 仅扩展标签和删除记录，避免数据双写不一致 |
| 版本机制 | 数据条目更新时不修改原行而是插入新行 + 标记旧行 `valid_to`，通过 `metadata.original_item_id` 串联版本历史 |
