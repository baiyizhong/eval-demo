# 自动评测模块需求

日期：2026-07-03

## 1. 背景与目标

自动评测模块用于在项目内创建、管理和执行自动评估任务。模块设计严格参考 Langfuse 社区版 Evaluators、Evaluation Rules、Job Configurations、Job Executions、Scores、Datasets 与 Traces 的数据结构和 API 能力，优先复用 Langfuse 原生接口与表结构，Plus 层仅做权限、响应格式、业务扩展和兼容封装。

本期目标：

- 创建自动评测任务。
- 查询自动评测任务列表，并展示任务状态。
- 页面顶部按任务状态展示统计信息。
- 创建任务采用三步流程：基础信息、选择评估器、选择评测数据。
- 评估器列表优先调用 Langfuse Evaluators API 查询。
- 评测数据支持从已有数据集中选择，也支持按 trace 过滤条件选择。
- trace 过滤条件参考 Langfuse trace 过滤能力，重点支持时间、环境等字段。
- 输入过滤条件后，提示符合条件的 trace 数量。
- 选择数据后支持配置采样率。
- 支持 badcase 收集开关；开启后需要配置评分达到多少时标识为 badcase。
- 创建完成后生成自动评测任务，并调度后续自动评测执行。

## 2. 设计原则

- Langfuse 兼容优先：评估器复用 `eval_templates`，评估规则/任务配置复用 `job_configurations`，执行实例复用 `job_executions`，评测结果复用 `scores`。
- API 优先复用：评估器列表优先复用 `GET /api/public/unstable/evaluators`；评估规则优先复用 `GET/POST/PATCH/DELETE /api/public/unstable/evaluation-rules`。
- 数据源复用：已有数据集复用 `datasets`、`dataset_items`；trace 过滤复用 Langfuse trace 查询与 filter 结构。
- 不改 Langfuse 原生表结构：禁止修改、删除或重命名 Langfuse 既有表结构。
- 扩展信息轻量存储：Langfuse 原生 `job_configurations` 无法完整表达 PA 任务三步配置快照、数据来源类型和 badcase 阈值时，新增 `pa_` 前缀扩展表。
- 数据库变更可回滚：新增 PA 表必须通过 Alembic 迁移脚本实现，并提供 downgrade。
- 写操作优先走 Langfuse API：创建、更新、删除评估规则优先调用 Langfuse API；确无对应 API 的 PA 扩展信息由 Plus 层自建接口写入自定义表。

## 3. 范围说明

### 3.1 本期范围

| 功能域 | 功能点 | 说明 |
| --- | --- | --- |
| 任务列表 | 查询自动评测任务 | 展示任务名称、评估器、数据来源、采样率、状态、执行统计、创建时间等 |
| 状态统计 | 顶部统计信息 | 按全部、启用、停用、待执行、执行中、成功、失败、取消等状态聚合 |
| 创建任务 | 第一步基础信息 | 录入任务名称、描述、项目、评分名称等 |
| 创建任务 | 第二步选择评估器 | 调用 Langfuse Evaluators API，选择 `llm_as_judge` 或 `code` 评估器 |
| 创建任务 | 第三步选择数据 | 支持已有数据集与 trace 过滤两种来源 |
| Trace 过滤 | 过滤条件配置 | 参考 Langfuse trace filter，至少支持时间、环境、trace name、userId、sessionId、tags、metadata |
| Trace 过滤 | 命中数量提示 | 输入过滤条件后展示符合条件的 trace 数量 |
| 执行配置 | 采样率 | 取值范围 `(0, 1]`，与 Langfuse `sampling` 保持一致 |
| Badcase | 收集开关与阈值 | 开启后配置评分阈值，命中阈值的评测结果标识为 badcase |
| 任务生成 | 创建自动评测任务 | 创建 Langfuse evaluation rule/job configuration，并保存 PA 扩展配置 |

### 3.2 非本期范围

- 新建或编辑评估器模板。
- 自定义评估器运行时。
- 修改 Langfuse 原生表结构。
- 直接修改 Langfuse trace、dataset、score 原生数据模型。
- 评测任务多级审批。
- badcase 的人工复核工作流。
- 评测结果看板和模型质量趋势分析。

## 4. Langfuse 数据模型复用

### 4.1 eval_templates

`eval_templates` 对应 Langfuse 评估器模板。

| 字段 | 说明 |
| --- | --- |
| `id` | 评估器 ID |
| `project_id` | 项目 ID；为空时表示全局模板 |
| `name` | 评估器名称 |
| `version` | 评估器版本 |
| `type` | 评估器类型，`LLM_AS_JUDGE` 或 `CODE` |
| `prompt` | LLM-as-judge 提示词 |
| `model` | 模型名称 |
| `provider` | 模型供应商 |
| `model_params` | 模型参数 |
| `vars` | 变量列表 |
| `output_schema` | 输出定义 |
| `source_code` | code evaluator 源码 |
| `source_code_language` | code evaluator 语言 |

前端展示评估器时，优先使用 Langfuse Public API 返回结构：

| API 字段 | Langfuse 来源 |
| --- | --- |
| `id` | `eval_templates.id` |
| `name` | `eval_templates.name` |
| `version` | `eval_templates.version` |
| `type` | `eval_templates.type` 映射为 `llm_as_judge` 或 `code` |
| `variables` | `eval_templates.vars` |
| `evaluationRuleCount` | 关联 evaluation rules 数量 |
| `createdAt` | `eval_templates.created_at` |
| `updatedAt` | `eval_templates.updated_at` |

### 4.2 job_configurations

`job_configurations` 对应 Langfuse evaluation rule，也是自动评测任务的核心配置。

| 字段 | 说明 |
| --- | --- |
| `id` | 任务配置 ID |
| `project_id` | 项目 ID |
| `job_type` | 固定复用 `EVAL` |
| `status` | 配置状态，`ACTIVE` 或 `INACTIVE` |
| `eval_template_id` | 关联评估器 |
| `score_name` | 评测输出分数名称 |
| `filter` | 过滤条件，复用 Langfuse `singleFilter[]` 结构 |
| `target_object` | 评测目标 |
| `variable_mapping` | 评估器变量映射 |
| `sampling` | 采样率，范围 `(0, 1]` |
| `delay` | 延迟执行时间 |
| `time_scope` | 时间范围，复用 `NEW`、`EXISTING` |
| `blocked_at` | 阻塞时间 |
| `block_reason` | 阻塞原因 |
| `block_message` | 阻塞说明 |

任务创建规则：

- 从已有数据集选择时，优先按 Langfuse `experiment` target 组织规则，过滤条件包含 dataset 维度。
- 从 trace 过滤选择时，优先按 Langfuse observation/event 评估规则组织，并将 trace 过滤条件转换为 Langfuse 支持的 filter/query。
- `sampling` 写入 Langfuse 原生字段。
- `filter` 与 `variable_mapping` 使用 Langfuse 原生结构，避免自定义不可兼容格式。

### 4.3 job_executions

`job_executions` 对应单次自动评测执行实例。

| 字段 | 说明 |
| --- | --- |
| `id` | 执行实例 ID |
| `project_id` | 项目 ID |
| `job_configuration_id` | 关联自动评测任务配置 |
| `job_template_id` | 执行时使用的评估器模板 |
| `status` | 执行状态，`PENDING`、`DELAYED`、`COMPLETED`、`ERROR`、`CANCELLED` |
| `start_time` | 开始时间 |
| `end_time` | 结束时间 |
| `error` | 错误信息 |
| `job_input_trace_id` | 输入 trace ID |
| `job_input_observation_id` | 输入 observation ID |
| `job_input_dataset_item_id` | 输入 dataset item ID |
| `job_output_score_id` | 输出 score ID |
| `execution_trace_id` | 评估器执行自身 trace ID |

任务列表中的执行统计从 `job_executions` 聚合：

| 展示字段 | 聚合口径 |
| --- | --- |
| 待执行数 | `status in (PENDING, DELAYED)` |
| 成功数 | `status = COMPLETED` |
| 失败数 | `status = ERROR` |
| 取消数 | `status = CANCELLED` |
| 最近执行时间 | `max(start_time)` 或 `max(updated_at)` |

### 4.4 scores

`scores` 存储自动评测结果。

| 字段 | 说明 |
| --- | --- |
| `id` | 分数 ID |
| `project_id` | 项目 ID |
| `trace_id` | 关联 trace |
| `observation_id` | 关联 observation |
| `name` | 分数名称，对应任务 `score_name` |
| `value` | 数值型评分 |
| `string_value` | 字符串型评分 |
| `data_type` | 分数类型 |
| `source` | 自动评测来源 |
| `comment` | 评估说明 |
| `created_at` | 创建时间 |

Badcase 判断规则：

- 自动评测执行完成后，根据 `job_output_score_id` 读取 score。
- 仅对可比较的评分类型执行阈值判断，优先支持 numeric score。
- 开启 badcase 收集后，若评分满足配置阈值，则在 PA 扩展表中标识为 badcase。
- 不修改 Langfuse `scores` 原生结构。

### 4.5 datasets 与 dataset_items

已有数据集作为评测数据来源时，复用 Langfuse 数据集结构。

| 模型 | 用途 |
| --- | --- |
| `datasets` | 数据集 |
| `dataset_items` | 评测样本 |
| `dataset_runs` | 数据集运行记录 |
| `dataset_run_items` | 数据集运行明细 |

选择已有数据集规则：

- 仅展示当前项目可访问的数据集。
- 用户选择一个数据集作为评测输入来源。
- 前端展示数据集名称、描述、样本数量、更新时间等信息。
- 创建任务时保存 dataset id 到 PA 扩展配置，并尽量转换为 Langfuse evaluation rule 支持的 experiment/dataset filter。

### 4.6 traces

trace 过滤数据来源复用 Langfuse trace 查询能力。

`GET /api/public/traces` 支持的关键查询参数包括：

| 参数 | 说明 |
| --- | --- |
| `fromTimestamp` | 起始时间 |
| `toTimestamp` | 结束时间 |
| `environment` | 环境，可单值或多值 |
| `name` | trace 名称 |
| `userId` | 用户 ID |
| `sessionId` | 会话 ID |
| `version` | 版本 |
| `release` | 发布版本 |
| `tags` | 标签 |
| `filter` | Langfuse `singleFilter[]` JSON 字符串 |

本模块 trace 过滤至少支持：

| 过滤字段 | 类型 | 说明 |
| --- | --- | --- |
| 时间 | datetime | 对应 `fromTimestamp`、`toTimestamp` 或 datetime filter |
| 环境 | stringOptions | 对应 `environment` |
| Trace Name | stringOptions/string | 对应 `name` 或 `traceName` |
| User ID | string | 对应 `userId` |
| Session ID | string | 对应 `sessionId` |
| Tags | arrayOptions | 对应 `tags` |
| Metadata | stringObject | 对应 `metadata` |
| Version | string | 对应 `version` |
| Release | string | 对应 `release` |

## 5. PA 扩展数据模型

Langfuse 原生任务配置不能完整保存 PA 页面三步配置快照、数据来源类型、命中数量和 badcase 阈值。本期新增轻量扩展表，表名必须以 `pa_` 开头。

### 5.1 pa_auto_eval_tasks

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | PA 自动评测任务 ID |
| `project_id` | string | 项目 ID |
| `job_configuration_id` | string | Langfuse `job_configurations.id` |
| `name` | string | 任务名称，冗余自 `job_configurations.score_name` 或创建表单名称 |
| `description` | text | 任务描述 |
| `data_source_type` | string | `DATASET` 或 `TRACE_FILTER` |
| `dataset_id` | string nullable | 数据集 ID，数据来源为数据集时必填 |
| `trace_filter` | json nullable | trace 过滤条件快照 |
| `matched_trace_count` | int nullable | 创建时命中的 trace 数量 |
| `sample_rate` | decimal | 采样率，保持与 `job_configurations.sampling` 一致 |
| `badcase_enabled` | boolean | 是否开启 badcase 收集 |
| `badcase_score_name` | string nullable | 用于 badcase 判断的 score 名称 |
| `badcase_operator` | string nullable | 阈值操作符，支持 `LT`、`LTE`、`GT`、`GTE`、`EQ` |
| `badcase_threshold` | decimal nullable | badcase 阈值 |
| `config_snapshot` | json | 三步表单配置快照 |
| `created_by` | string | 创建人 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

约束与索引：

- `job_configuration_id` 唯一。
- `project_id + created_at` 建索引，用于任务列表排序。
- `project_id + data_source_type` 建索引，用于筛选。
- 该表只保存 PA 扩展信息，不替代 Langfuse 任务配置。

### 5.2 pa_auto_eval_badcases

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | badcase 记录 ID |
| `project_id` | string | 项目 ID |
| `auto_eval_task_id` | string | `pa_auto_eval_tasks.id` |
| `job_execution_id` | string | Langfuse `job_executions.id` |
| `score_id` | string | Langfuse `scores.id` |
| `trace_id` | string nullable | trace ID |
| `observation_id` | string nullable | observation ID |
| `dataset_item_id` | string nullable | dataset item ID |
| `score_name` | string | 分数名称 |
| `score_value` | decimal nullable | 数值评分 |
| `threshold_operator` | string | 命中操作符 |
| `threshold_value` | decimal | 阈值 |
| `created_at` | datetime | 创建时间 |

约束与索引：

- `job_execution_id + score_id` 唯一，避免重复收集。
- `project_id + auto_eval_task_id + created_at` 建索引。
- 不写入 Langfuse 原生表字段，不影响 Langfuse score 展示。

## 6. 功能需求

### 6.1 自动评测任务列表

入口：评测管理下新增“自动评测”模块。

列表字段：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | PA 扩展表 `name` 或 Langfuse evaluation rule name |
| 评估器 | `eval_templates.name + version` |
| 数据来源 | 数据集名称或 trace 过滤 |
| 采样率 | `job_configurations.sampling` |
| 任务状态 | 由 `job_configurations.status` 与最近执行状态聚合 |
| 待执行数 | `job_executions` 聚合 |
| 成功数 | `job_executions` 聚合 |
| 失败数 | `job_executions` 聚合 |
| Badcase 数 | `pa_auto_eval_badcases` 聚合 |
| 创建人 | `pa_auto_eval_tasks.created_by` |
| 创建时间 | `pa_auto_eval_tasks.created_at` |
| 操作 | 查看详情、启用、停用、删除 |

任务状态映射：

| 页面状态 | 判断规则 |
| --- | --- |
| 启用 | `job_configurations.status = ACTIVE` 且无阻塞 |
| 停用 | `job_configurations.status = INACTIVE` |
| 阻塞 | `blocked_at is not null` 或 `block_reason is not null` |
| 待执行 | 存在 `PENDING` 或 `DELAYED` execution |
| 执行成功 | 最近一次 execution 为 `COMPLETED` |
| 执行失败 | 最近一次 execution 为 `ERROR` |
| 已取消 | 最近一次 execution 为 `CANCELLED` |

### 6.2 顶部状态统计

页面顶部展示状态统计卡片：

| 统计项 | 口径 |
| --- | --- |
| 全部任务 | 当前项目自动评测任务总数 |
| 启用中 | `job_configurations.status = ACTIVE` |
| 已停用 | `job_configurations.status = INACTIVE` |
| 待执行 | 存在 `PENDING` 或 `DELAYED` execution |
| 执行成功 | 最近一次 execution 为 `COMPLETED` |
| 执行失败 | 最近一次 execution 为 `ERROR` |
| Badcase | `pa_auto_eval_badcases` 总数或按任务去重数 |

点击统计项后，列表按对应状态筛选。

### 6.3 创建自动评测任务：第一步基础信息

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 任务名称 | 是 | 项目内建议唯一，展示在任务列表 |
| 任务描述 | 否 | 说明评测目的 |
| Score Name | 是 | 写入 Langfuse `job_configurations.score_name`，也作为输出 score 名称 |
| 执行延迟 | 否 | 写入 `job_configurations.delay`，默认沿用 Langfuse 默认值 |

校验规则：

- 任务名称不能为空。
- Score Name 不能为空，只允许项目内可识别的 score 名称格式。
- 同一项目内不允许创建完全同名且同 score name 的启用任务，避免重复评测。

### 6.4 创建自动评测任务：第二步选择评估器

评估器列表来源：

- 优先调用 Langfuse `GET /api/public/unstable/evaluators`。
- Plus 层封装为当前项目内部接口，统一返回 `{ code, message, data, txId }`。

展示字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | evaluator `name` |
| 类型 | `llm_as_judge` 或 `code` |
| 版本 | evaluator `version` |
| 变量 | evaluator `variables` |
| 已关联规则数 | `evaluationRuleCount` |
| 更新时间 | `updatedAt` |

选择规则：

- 单个任务只能选择一个评估器。
- `llm_as_judge` 评估器需要配置变量映射。
- `code` 评估器变量映射遵循 Langfuse 机制，不允许提交不兼容 mapping。
- 变量映射字段应直接复用 Langfuse `mapping` 结构。

### 6.5 创建自动评测任务：第三步选择评测数据

第三步分为数据来源、命中预览、执行配置三部分。

#### 6.5.1 数据来源：已有数据集

用户选择“已有数据集”时：

- 展示当前项目数据集列表。
- 支持按数据集名称搜索。
- 展示数据集名称、描述、样本数量、最近更新时间。
- 选择后展示该数据集可评测样本数量。
- 创建任务时保存 `data_source_type = DATASET`、`dataset_id`。

#### 6.5.2 数据来源：trace 过滤

用户选择“trace 过滤”时：

- 过滤条件 UI 参考 Langfuse trace 页面与 evaluation rule filter。
- 至少支持时间范围、环境字段。
- 时间范围必填，避免无边界扫描。
- 环境可多选。
- 可选扩展字段包括 trace name、userId、sessionId、tags、metadata、version、release。
- 过滤条件保存为 Langfuse `singleFilter[]` 兼容结构和 trace 查询参数快照。

命中数量提示：

- 用户填写或修改过滤条件后，点击“预估数量”或自动防抖查询。
- Plus 层调用 Langfuse trace 查询或 ClickHouse 计数能力，返回符合条件的 trace 数量。
- 页面展示“预计命中 N 条 trace”。
- 若命中数量为 0，禁止进入创建确认。
- 若命中数量过大，提示用户缩小时间范围或降低采样率。

#### 6.5.3 采样率配置

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 采样率 | 是 | 范围 `(0, 1]`，默认 `1` |

规则：

- `1` 表示全量评测。
- `0.1` 表示按 10% 采样。
- 创建任务时写入 `job_configurations.sampling`，并冗余保存到 `pa_auto_eval_tasks.sample_rate`。

#### 6.5.4 Badcase 收集配置

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| Badcase 收集 | 是 | 开关，默认关闭 |
| 判断分数 | 开启后必填 | 默认使用第一步填写的 Score Name |
| 操作符 | 开启后必填 | 支持小于、小于等于、大于、大于等于、等于 |
| 阈值 | 开启后必填 | 数值型阈值 |

规则：

- 仅当评测输出 score 为 numeric 时，支持阈值判断。
- 开启后必须填写阈值。
- 示例：`score <= 0.6` 标识为 badcase。
- 自动评测执行完成后，Plus 层根据 `job_executions.job_output_score_id` 查询 score 并写入 `pa_auto_eval_badcases`。

### 6.6 创建完成与任务生成

提交创建时，Plus 层按以下顺序执行：

1. 校验基础信息、评估器、数据来源、采样率和 badcase 配置。
2. 调用 Langfuse API 创建 evaluation rule，或复用 Langfuse internal eval create 能力创建 `job_configurations`。
3. 写入 `pa_auto_eval_tasks`，保存 PA 扩展信息与表单快照。
4. 若数据来源为历史 trace 或已有数据集，调度批量评测执行，优先复用 Langfuse batch action 机制。
5. 返回自动评测任务详情。

失败处理：

- 如果 Langfuse 任务创建失败，不写入 PA 扩展表。
- 如果 PA 扩展表写入失败，应回滚或停用已创建的 Langfuse evaluation rule，并记录审计日志。
- 不向前端暴露内部异常细节。

## 8. 数据流

### 8.1 创建任务数据流

1. 前端填写基础信息。
2. 前端通过 Plus 层查询 Langfuse evaluators。
3. 前端选择已有数据集或配置 trace 过滤条件。
4. trace 过滤模式下，Plus 层返回命中数量。
5. 前端配置采样率和 badcase 阈值。
6. Plus 层创建 Langfuse evaluation rule/job configuration。
7. Plus 层写入 `pa_auto_eval_tasks`。
8. Langfuse 调度 `job_executions` 并生成 `scores`。
9. Plus 层根据 badcase 配置识别并写入 `pa_auto_eval_badcases`。

### 8.2 查询列表数据流

1. 前端请求自动评测任务列表。
2. Plus 层查询 `pa_auto_eval_tasks`。
3. Plus 层关联 Langfuse `job_configurations`、`eval_templates`、`job_executions`。
4. Plus 层聚合执行状态与 badcase 数量。
5. 前端展示列表和顶部统计。

## 9. 权限与安全

- 仅项目内有评测管理权限的用户可创建、启用、停用和删除自动评测任务。
- 仅项目内有查看权限的用户可查看任务列表和统计信息。
- Langfuse API Key、数据库连接串、内部 token 必须来自 `.env` 或环境变量，禁止写入代码。
- 请求参数必须使用 Pydantic schema 校验。
- SQL 查询必须使用 SQLAlchemy 参数绑定。
- 关键操作记录审计日志，包括创建任务、启用、停用、删除、badcase 规则变更。
- 错误响应不得暴露 Langfuse token、数据库连接串或内部 SQL。

## 10. 异常处理

| 场景 | 处理 |
| --- | --- |
| 评估器不存在 | 返回业务错误，提示重新选择评估器 |
| 评估器被禁用或不可用 | 返回业务错误，并展示 Langfuse 阻塞原因摘要 |
| trace 命中数量为 0 | 禁止创建任务 |
| trace 命中数量过大 | 允许创建前提示风险，建议调整时间范围或采样率 |
| sampling 不合法 | 返回参数错误 |
| badcase 开启但阈值为空 | 返回参数错误 |
| badcase 阈值用于非 numeric score | 返回业务错误或禁用 badcase 开关 |
| Langfuse API 调用失败 | 返回统一错误格式，并记录 txId |
| PA 扩展表写入失败 | 回滚或停用已创建的 Langfuse 任务，并记录审计日志 |

## 11. 验收标准

- 能在 `docs/prd/` 中看到本需求文档。
- 自动评测列表展示任务状态和执行统计。
- 页面顶部能按任务状态展示统计信息，并支持筛选列表。
- 创建任务分三步完成：基础信息、选择评估器、选择评测数据。
- 评估器选择通过 Langfuse Evaluators API 获取，不重复建设评估器模型。
- 评测数据支持已有数据集和 trace 过滤两种来源。
- trace 过滤至少支持时间和环境字段。
- 输入 trace 过滤条件后，能展示符合条件的 trace 数量。
- 采样率配置写入 Langfuse `job_configurations.sampling`。
- badcase 开启后必须填写评分阈值。
- 创建完成后生成 Langfuse 自动评测任务配置，并保存 PA 扩展配置。
- 不修改 `langfuse/` 目录源码。
- 不修改 Langfuse 原生表结构。
- 所有新增 PA 表以 `pa_` 开头，并通过 Alembic 迁移支持回滚。
