# 应用观测模块需求描述

## 1. 背景与目标

应用观测模块用于承接 Agent、LLM 应用在运行过程中的 Trace 数据查看、统计分析、异常定位和标注数据沉淀。用户可以通过 Trace 看板快速了解当前项目的运行健康度，也可以通过 Trace 日志定位单条调用链，查看输入、输出、元数据和调用过程。

本模块第一版目标：

- 在项目详情中新增“应用观测”菜单，并提供“Trace 看板”和“Trace 日志”两个子页面。
- Trace 看板展示当前项目在指定时间范围内的核心运维指标，包括 Trace 总量、成功/失败量、失败率、平均延迟、P95 延迟、趋势、环境分布和慢 Trace 排名。
- Trace 日志提供 Trace 列表、普通筛选、高级筛选、分页、多选和批量操作。
- Trace 日志默认展示 `traceId`、`sessionId`、环境、状态、延迟、创建时间。
- 用户点击 Trace 列表项后，通过右侧抽屉查看 Trace 详情，包括 Trace 调用链、`input`、`output`、`metadata`。
- 用户可在详情抽屉中切换到编辑态，修改 `input`、`output`、`metadata` 并保存。
- Trace 列表支持多选后导出所选 Trace。
- Trace 列表支持多选后进入人工标注任务创建入口，并携带所选 Trace 范围。

设计原则：

- 查询类能力优先通过 PA 自建接口读取数据库，复用已有查询接口。
- 新增、修改、删除类能力优先通过 Langfuse API；如果 Langfuse API 不支持对应写入能力，实施前需确认是否新增 PA 自建接口。
- 不修改 `langfuse/` 目录源码，不修改 Langfuse 原生表结构。
- 不直接对 Langfuse 原生表做新增、修改、删除，除非用户明确授权且没有可用接口路径。

参考资料：

- [Langfuse Tracing](https://langfuse.com/docs/tracing)
- [Langfuse Scores and Evaluations](https://langfuse.com/docs/scores/overview)
- 前端 Trace 调用链组件：`pa-eval-frontend/spec/40-components/business/llm-trace-chain.md`

## 3. 数据模型设计

### 3.1 沿用 Langfuse 原生模型

| 模型 | 用途 | 说明 |
| --- | --- | --- |
| `Project` | 项目基础信息 | Trace 数据归属于项目 |
| `Trace` | Trace 基础信息 | 记录一次应用调用或会话内调用链入口 |
| `Observation` | 调用链节点 | 记录 LLM、Tool、Chain、Agent 等调用步骤 |
| `Score` | 评分或标注结果 | 后续人工标注和评测结果可关联 Trace |

本期不新增 Trace 扩展表。Trace 列表、详情、看板统计优先读取 Langfuse 原生 Trace、Observation 等数据。

### 3.2 Trace 列表字段

| 字段 | 说明 | 来源建议 |
| --- | --- | --- |
| `traceId` | Trace 唯一标识 | Langfuse Trace ID |
| `sessionId` | 会话标识 | Langfuse Trace sessionId |
| `projectId` | 所属项目 ID | Trace 所属项目 |
| `projectName` | 所属项目名称 | Project.name |
| `environment` | 环境 | Trace 环境字段或 metadata 中的环境字段 |
| `status` | 状态 | 根据 Trace 或 Observation 错误状态计算 |
| `latency` | Trace 总耗时 | 根据开始和结束时间或 Observation 聚合计算 |
| `createdAt` | 创建时间 | Trace 创建时间 |
| `userId` | 用户标识 | Trace userId 或 metadata 中的业务用户标识 |
| `businessId` | 业务标识 | metadata 中的业务 ID |
| `tags` | 标签 | Trace tags 或 metadata 标签 |
| `metadata` | 元数据 | Trace metadata |

状态计算建议：

- 如果 Trace 或任一关键 Observation 存在错误状态，则 Trace 状态为失败。
- 如果 Trace 已结束且无错误状态，则 Trace 状态为成功。
- 如果 Trace 尚未结束或缺少结束时间，可展示为运行中或未知。
- 状态枚举在接口层应统一映射，避免前端直接理解底层多种状态值。

### 3.3 Trace 详情字段

| 字段 | 说明 |
| --- | --- |
| `traceId` | Trace 唯一标识 |
| `sessionId` | 会话标识 |
| `environment` | 环境 |
| `status` | 状态 |
| `latency` | 总耗时 |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |
| `input` | Trace 输入，字符串展示 |
| `output` | Trace 输出，字符串展示 |
| `metadata` | Trace 元数据，JSON 展示 |
| `callChain` | Trace 调用链树形数据 |

`callChain` 应转换为前端 `LLMTraceChain` 组件可消费的数据结构：

```ts
interface TreeNode {
  id: string;
  type: string;
  title: string;
  duration?: string;
  cost?: string;
  tokensIn?: number;
  tokensOut?: number;
  tokensTotal?: number;
  tags?: string[];
  children?: TreeNode[];
}
```

### 3.4 编辑字段

本期仅支持编辑 Trace 顶层字段：

| 字段 | 类型 | 校验规则 |
| --- | --- | --- |
| `input` | string | 可为空；建议限制最大长度，超限时提示用户 |
| `output` | string | 可为空；建议限制最大长度，超限时提示用户 |
| `metadata` | object | 必须为合法 JSON 对象，不允许写入数组或非 JSON 对象 |

编辑保存规则：

- 保存时只更新本期允许编辑的字段，不覆盖其他 Trace 字段。
- `metadata` 保存必须做 JSON schema 或 Pydantic/Zod 校验。
- 不允许编辑 Trace ID、项目 ID、创建时间、调用链节点等系统字段。
- 如果 Langfuse API 支持更新对应字段，应优先通过 Langfuse API 保存。
- 如果 Langfuse API 不支持更新对应字段，需在实施前确认是否新增 PA 自建接口；新增接口必须记录审计日志。

## 4. 页面与交互

### 4.1 菜单结构

入口：

- 用户进入项目详情后，在项目级导航中展示“应用观测”菜单。
- “应用观测”下包含两个子页面：“Trace 看板”和“Trace 日志”。

默认进入规则：

- 用户点击“应用观测”时，默认进入“Trace 看板”。
- 用户从 Trace 看板点击慢 Trace、失败 Trace 或趋势图明细时，可跳转到 Trace 日志并带入筛选条件。

页面上下文：

- 当前组织和当前项目由全局上下文或项目详情路由决定。
- Trace 查询默认限定在当前项目内。
- 页面筛选、分页、排序应支持通过 URL query 表达，便于复制链接和刷新恢复。

### 4.2 Trace 看板

入口：

- 应用观测 / Trace 看板。

筛选区：

| 筛选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 时间范围 | 日期时间范围 | 最近 24 小时 | 用于统计查询 |
| 环境 | 多选 | 全部 | 支持按生产、预发、测试等环境筛选 |

指标卡片：

| 指标 | 说明 | 展示要求 |
| --- | --- | --- |
| Trace 总量 | 时间范围内 Trace 总数 | 展示总数和较上一周期变化 |
| 成功量 | 成功 Trace 数量 | 展示数量和占比 |
| 失败量 | 失败 Trace 数量 | 展示数量和占比 |
| 失败率 | 失败量 / Trace 总量 | 百分比展示 |
| 平均延迟 | Trace 平均耗时 | 支持 ms/s 自适应展示 |
| P95 延迟 | Trace P95 耗时 | 支持 ms/s 自适应展示 |

图表：

| 图表 | 说明 |
| --- | --- |
| Trace 趋势 | 按时间粒度展示 Trace 总量和失败量变化 |
| 延迟趋势 | 按时间粒度展示平均延迟和 P95 延迟变化 |
| 环境分布 | 展示各环境 Trace 数量分布 |
| 慢 Trace 排名 | 展示耗时最高的 Trace 列表 |

慢 Trace 排名字段：

| 字段 | 说明 |
| --- | --- |
| `traceId` | Trace ID，可点击跳转详情 |
| `sessionId` | 会话 ID |
| 环境 | Trace 所属环境 |
| 状态 | 成功、失败、运行中或未知 |
| 延迟 | Trace 总耗时 |
| 创建时间 | Trace 创建时间 |

交互规则：

1. 用户调整时间范围或环境后，看板指标和图表刷新。
2. 用户点击失败量、失败率、慢 Trace 排名中的 Trace，可跳转到 Trace 日志或打开 Trace 详情。
3. 看板数据加载中展示骨架屏或加载态。
4. 无数据时展示空状态，例如“当前筛选条件下暂无 Trace 数据”。
5. 接口异常时展示可重试错误态，不暴露内部异常信息。

### 4.3 Trace 日志列表

入口：

- 应用观测 / Trace 日志。

列表默认列：

| 列名 | 字段 | 说明 |
| --- | --- | --- |
| Trace ID | `traceId` | 可点击打开详情抽屉 |
| Session ID | `sessionId` | 支持复制 |
| 环境 | `environment` | 使用文本或标签展示 |
| 状态 | `status` | 成功、失败、运行中、未知 |
| 延迟 | `latency` | 按耗时格式化展示 |
| 创建时间 | `createdAt` | 按系统统一时间格式展示 |

列表行为：

- 支持分页，分页参数统一使用 `page` 和 `pageSize`。
- 支持按创建时间倒序排序，默认最新 Trace 在前。
- 支持多选，选中后展示批量操作区。
- Trace ID、Session ID 等长文本应支持复制和省略展示。
- 列表刷新后应保留当前筛选条件和分页状态。

### 4.4 普通筛选

普通筛选位于列表顶部，默认展开。

| 筛选项 | 说明 |
| --- | --- |
| 时间范围 | 按 Trace 创建时间筛选 |
| ID 搜索 | 支持输入 traceId 或 sessionId 精确/模糊搜索 |

交互规则：

1. 时间范围默认继承页面默认值，例如最近 24 小时。
2. 用户输入 ID 后点击查询，列表按 traceId 或 sessionId 搜索。
3. 清空筛选后恢复默认时间范围和当前项目上下文。
4. 普通筛选与高级筛选同时生效。

### 4.5 高级筛选

高级筛选默认收起，用户点击“高级筛选”后展开。

| 筛选项 | 类型 | 说明 |
| --- | --- | --- |
| 项目 | 下拉选择 | 默认当前项目；如当前页面只允许项目内查看，可置灰 |
| 环境 | 多选 | 支持按环境筛选 |
| 状态 | 多选 | 支持成功、失败、运行中、未知 |
| 延迟区间 | 数值区间 | 支持设置最小和最大耗时 |
| Session ID | 输入框 | 支持按 sessionId 筛选 |
| 用户标识 | 输入框 | 支持按 userId 筛选 |
| 业务标识 | 输入框 | 支持按业务 ID 筛选 |
| 标签 | 多选或输入 | 支持按 tags 筛选 |
| metadata key/value | 动态条件 | 支持添加多个 key/value 条件 |

metadata 筛选规则：

- key 不能为空。
- value 可为空；value 为空时表示筛选存在该 key 的 Trace。
- 多个 metadata 条件默认按 AND 关系组合。
- 后端必须使用参数绑定或结构化查询，防止注入风险。

### 4.6 Trace 详情抽屉

打开方式：

- 用户点击 Trace 列表行或 Trace ID。
- 用户从 Trace 看板慢 Trace 排名点击单条 Trace。

展示结构：

| 区域 | 内容 | 说明 |
| --- | --- | --- |
| 抽屉头部 | traceId、状态、环境、创建时间 | 提供复制 Trace ID 操作 |
| 概览信息 | sessionId、延迟、更新时间等 | 展示核心基础字段 |
| Trace 调用链 | 调用链树 | 复用 `LLMTraceChain` 数据结构和交互口径 |
| Input | 输入内容 | 字符串展示，支持复制 |
| Output | 输出内容 | 字符串展示，支持复制 |
| Metadata | JSON 内容 | JSON 格式化展示，支持复制 |

调用链要求：

- 支持节点展开、折叠、搜索和元信息展示。
- 节点类型优先映射为 `ingress`、`agent`、`run`、`response`、`tool`、`retrieval`、`prompt`、`guard`、`eval` 等已定义类型。
- 节点耗时、Token、费用等字段有值时展示，无值时不展示空占位。
- 调用链为空时展示空状态，不影响 input、output、metadata 查看。

### 4.7 Trace 编辑

入口：

- Trace 详情抽屉中展示“编辑”按钮。

可编辑内容：

- `input`
- `output`
- `metadata`

交互规则：

1. 用户点击“编辑”后，抽屉进入编辑态。
2. `input`、`output` 使用多行文本输入。
3. `metadata` 使用 JSON 编辑区或结构化 JSON 输入组件。
4. 用户点击“保存”后，前端先校验 metadata 是否为合法 JSON 对象。
5. 保存中禁用保存按钮并展示加载态。
6. 保存成功后返回查看态，并刷新详情和列表必要字段。
7. 保存失败时保留用户输入并展示错误提示。
8. 用户点击“取消”时，若存在未保存修改，应提示是否放弃修改。

审计要求：

- 成功保存 Trace 编辑时，后端需要记录操作者、项目 ID、Trace ID、变更前后内容摘要、操作时间和 txId。
- 日志中不得记录敏感密钥或内部 token。

### 4.8 批量导出

入口：

- Trace 日志列表多选后展示“导出”按钮。

导出范围：

- 只导出用户当前选中的 Trace。
- 如果用户未选择 Trace，导出按钮置灰或提示“请选择需要导出的 Trace”。

导出内容：

| 字段 | 说明 |
| --- | --- |
| `traceId` | Trace ID |
| `sessionId` | Session ID |
| `projectId` | 项目 ID |
| `environment` | 环境 |
| `status` | 状态 |
| `latency` | 延迟 |
| `createdAt` | 创建时间 |
| `input` | 输入 |
| `output` | 输出 |
| `metadata` | 元数据 |

导出格式：

- 首版建议支持 JSON 或 CSV；如果只能实现一种，优先 JSON，避免复杂字段在 CSV 中丢失结构。
- 文件名建议包含项目 ID、导出时间和 Trace 数量，例如 `traces-project_xxx-20260703-120000.json`。

### 4.9 人工标注入口

入口：

- Trace 日志列表多选后展示“人工标注”按钮。

本期范围：

- 用户选择一个或多个 Trace 后，点击“人工标注”。
- 系统创建人工标注任务或跳转人工标注创建页，并携带所选 Trace ID 列表。
- 人工标注任务创建后，标注工作台、标注表单、质检流程和结果统计由人工标注模块另行定义。

交互规则：

1. 未选择 Trace 时，按钮置灰或提示“请选择需要标注的 Trace”。
2. 若所选 Trace 中存在不存在或不可用的数据，后端应返回可展示错误信息。
3. 成功创建或跳转后，页面应清晰展示所选 Trace 数量。
4. 不允许前端仅依赖当前页数据创建任务，后端必须重新校验 Trace ID 列表。

## 5. API 需求

接口设计应遵循项目统一 API 规范：

- RESTful 风格，资源命名使用复数名词。
- 分页参数统一使用 `page` 和 `pageSize`。
- 响应格式统一为 `{ code: number, message: string, data: any, txId: string }`。
- 成功响应 `code` 为 `0`，`message` 默认为 `success`。
- 错误响应 `code` 非 `0`，`message` 返回可展示错误信息。

### 5.1 建议接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/projects/{projectId}/trace-metrics` | 查询 Trace 看板指标 |
| `GET` | `/projects/{projectId}/traces` | 查询 Trace 日志列表 |
| `GET` | `/projects/{projectId}/traces/{traceId}` | 查询 Trace 详情 |
| `PATCH` | `/projects/{projectId}/traces/{traceId}` | 编辑 Trace input、output、metadata |
| `POST` | `/projects/{projectId}/traces/export` | 导出所选 Trace |
| `POST` | `/projects/{projectId}/annotation-tasks` | 基于所选 Trace 创建人工标注入口 |

说明：

- 查询类接口优先由 PA 后端封装数据库查询和 Langfuse 数据结构转换。
- `PATCH /projects/{projectId}/traces/{traceId}` 是否落地取决于 Langfuse API 能否支持对应字段更新；如果不能支持，实施前需确认 PA 自建接口方案。
- 人工标注接口只定义入口和 Trace 选择结果，不定义完整标注任务模型。

## 6. 异常处理

| 场景 | 处理方式 |
| --- | --- |
| Trace 不存在 | 返回资源不存在，前端展示“Trace 不存在或已不可用” |
| 筛选参数非法 | 返回参数错误，前端定位到对应筛选项 |
| metadata JSON 非法 | 前端阻断保存并提示“请输入合法 JSON 对象” |
| 导出数量为空 | 前端提示“请选择需要导出的 Trace” |
| 导出数量过大 | 后端返回业务错误，前端提示缩小选择范围 |
| Langfuse 查询失败 | 返回可展示错误，不暴露内部实现细节 |
| 保存冲突 | 返回状态不允许或资源冲突，前端提示刷新后重试 |

错误码建议复用平台统一错误码：

```text
0      success
1001   参数错误
1004   资源不存在
1005   资源冲突
1006   状态不允许
2001   Langfuse 接口调用失败
2002   Langfuse 数据不一致
5000   系统内部错误
```

## 7. 安全与审计

安全要求：

- 外部输入必须校验，包括时间范围、ID、状态、延迟区间、metadata 条件和分页参数。
- SQL 查询必须使用参数绑定，禁止拼接用户输入。
- `input`、`output`、`metadata` 可能包含敏感信息，日志中不得直接打印完整内容。
- 导出接口需校验导出数量和文件大小，避免一次性导出过大数据。
- 前端不得硬编码 API 地址、密钥或数据库连接信息。

审计要求：

| 操作 | 是否审计 | 说明 |
| --- | --- | --- |
| 查看 Trace 列表 | 否 | 可通过访问日志记录 |
| 查看 Trace 详情 | 可选 | 如涉及敏感数据，可记录访问审计 |
| 编辑 Trace | 是 | 记录变更摘要 |
| 导出 Trace | 是 | 记录导出数量和筛选范围 |
| 创建人工标注入口 | 是 | 记录所选 Trace 数量和任务 ID |

审计字段建议：

```text
tx_id
actor_user_id
org_id
project_id
resource_type
resource_id
action
before
after
created_at
```

## 9. 风险与约束

- Langfuse API 对 Trace 顶层字段的更新能力需要实施前验证；如果不支持，需要确认 PA 自建接口方案。
- Trace 状态和延迟可能来自多张表或多种事件状态，后端需要统一映射口径，避免前端重复计算。
- metadata key/value 筛选在数据量较大时可能存在性能风险，首版应限制查询条件数量，并关注索引或查询计划。
- 导出大批量 Trace 可能影响服务性能，首版应限制单次导出数量。
- Trace input/output/metadata 可能包含敏感业务数据，导出和审计策略需要与安全要求一致。
- 人工标注模块尚未完整定义，本 PRD 仅要求提供入口和所选 Trace 传递能力。
