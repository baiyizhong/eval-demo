# 项目设置模块需求描述

日期：2026-07-03

## 1. 背景与目标

项目设置模块用于管理单个项目的基础信息、评分指标、项目成员、模型配置与项目级 API Keys。模块设计严格参考 Langfuse 社区版 Project Settings 的能力和数据结构，优先复用 Langfuse 原生表、权限模型与 API，Plus 层仅做统一鉴权、响应格式封装和少量业务适配。

本期目标：

- 提供项目设置页，分区包含通用设置、评分指标、项目成员、模型设置、API Keys。
- 通用设置支持查看和编辑项目基础信息。
- 评分指标支持查询、新增、编辑、归档，复用 Langfuse Score Configs。
- 项目成员支持查询、新增、删除和修改成员权限。
- 项目成员角色支持项目 `owner`、项目 `admin`、项目 `member`、项目 `viewer`。
- 模型设置复用 Langfuse Models、LLM Connections 与 Default LLM Model 机制。
- API Keys 支持查询、新增、编辑备注和删除项目级 API Key。

## 2. 设计原则

- Langfuse 兼容优先：项目、成员、评分指标、模型、API Key 均优先复用 Langfuse 原生结构。
- 不改 Langfuse 原生表结构：禁止修改 Langfuse 既有表结构；确需扩展时优先写入原生 JSON 字段。
- 本期不新增 PA 扩展表：项目设置能力可由 `projects`、`project_memberships`、`score_configs`、`models`、`llm_api_keys`、`default_llm_models`、`api_keys` 承接。
- 写操作优先复用 Langfuse API 或 router：API Keys、评分指标、模型和成员管理尽量调用 Langfuse 已有接口能力。
- 权限与审计一致：沿用 Langfuse RBAC scope，关键操作记录审计日志。
- 敏感信息安全：API Key、LLM Secret Key 只返回脱敏值，创建成功时完整 secret 仅展示一次。

## 4. Langfuse 数据模型复用

### 4.1 projects

`projects` 对应项目基础信息。

| 字段 | 说明 |
| --- | --- |
| `id` | 项目 ID |
| `org_id` | 所属组织 ID |
| `name` | 项目名称 |
| `metadata` | JSON 扩展字段，可承接项目描述 |
| `retention_days` | 数据保留天数 |
| `deleted_at` | 归档时间，非空表示项目已归档 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

项目描述建议继续沿用项目管理模块约定，写入 `projects.metadata.description`。

```json
{
  "description": "用于 Agent 评测的核心业务项目"
}
```

### 4.2 project_memberships

`project_memberships` 对应用户在单个项目内的项目角色。

| 字段 | 说明 |
| --- | --- |
| `project_id` | 项目 ID |
| `user_id` | 用户 ID |
| `org_membership_id` | 用户在项目所属组织内的成员关系 ID |
| `role` | 项目角色 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

主键和约束：

- 主键为 `project_id + user_id`。
- 同一用户在同一项目内只能拥有一个项目角色。
- 项目成员必须能关联到项目所属组织内的 `organization_memberships`。

### 4.3 Role 枚举

项目成员角色沿用 Langfuse `Role` 枚举：

| 页面角色 | 数据库枚举 | 定位 |
| --- | --- | --- |
| 项目 owner | `OWNER` | 项目最高权限，可管理项目设置、成员、Key 和模型 |
| 项目 admin | `ADMIN` | 项目管理员，可管理大部分项目设置 |
| 项目 member | `MEMBER` | 项目普通成员，可使用项目业务功能 |
| 项目 viewer | `VIEWER` | 项目只读成员 |

`NONE` 仅用于 Langfuse 内部邀请和角色清空语义，不作为页面可授予的项目角色展示。

### 4.4 score_configs

`score_configs` 对应项目评分指标。

| 字段 | 说明 |
| --- | --- |
| `id` | 指标 ID |
| `project_id` | 项目 ID |
| `name` | 指标名称 |
| `data_type` | 指标类型，`NUMERIC`、`CATEGORICAL`、`BOOLEAN`、`TEXT` |
| `min_value` | 数值型最小值 |
| `max_value` | 数值型最大值 |
| `categories` | 分类型选项 |
| `description` | 指标说明 |
| `is_archived` | 是否归档 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

评分指标 API 优先复用 Langfuse Public API：

- `GET /api/public/score-configs`
- `GET /api/public/score-configs/{configId}`
- `POST /api/public/score-configs`
- `PUT /api/public/score-configs/{configId}`

### 4.5 models、prices、pricing_tiers

`models` 对应 Langfuse 模型匹配与计价配置。

| 字段 | 说明 |
| --- | --- |
| `id` | 模型配置 ID |
| `project_id` | 项目 ID；为空表示 Langfuse 内置模型 |
| `model_name` | 模型名称 |
| `match_pattern` | 匹配规则 |
| `start_date` | 生效日期 |
| `input_price` | 输入价格，兼容旧结构 |
| `output_price` | 输出价格，兼容旧结构 |
| `total_price` | 总价，兼容旧结构 |
| `unit` | 计价单位 |
| `tokenizer_id` | tokenizer |
| `tokenizer_config` | tokenizer 配置 |

`prices` 与 `pricing_tiers` 用于阶梯价格：

| 模型 | 用途 |
| --- | --- |
| `pricing_tiers` | 价格阶梯、匹配条件、优先级 |
| `prices` | 每个阶梯下不同 usage type 的价格 |

模型定义 API 优先复用 Langfuse Models API：

- `GET /api/public/models`
- `GET /api/public/models/{modelId}`
- `POST /api/public/models`
- `DELETE /api/public/models/{modelId}`

### 4.6 llm_api_keys 与 default_llm_models

`llm_api_keys` 对应项目内 LLM Provider 连接。

| 字段 | 说明 |
| --- | --- |
| `id` | LLM 连接 ID |
| `project_id` | 项目 ID |
| `provider` | Provider 名称 |
| `adapter` | 适配器，如 OpenAI、Anthropic、Bedrock、VertexAI |
| `display_secret_key` | 脱敏后的密钥 |
| `secret_key` | 加密后的密钥 |
| `base_url` | 自定义 Base URL |
| `custom_models` | 自定义模型列表 |
| `with_default_models` | 是否包含默认模型 |
| `extra_headers` | 加密后的额外请求头 |
| `extra_header_keys` | 请求头 key 列表 |
| `config` | Provider 特定配置 |

`default_llm_models` 对应项目默认评估模型。

| 字段 | 说明 |
| --- | --- |
| `id` | 默认模型配置 ID |
| `project_id` | 项目 ID |
| `llm_api_key_id` | 使用的 LLM 连接 ID |
| `provider` | Provider |
| `adapter` | Adapter |
| `model` | 默认模型名称 |
| `model_params` | 默认模型参数 |

### 4.7 api_keys

`api_keys` 对应项目级 API Key。

| 字段 | 说明 |
| --- | --- |
| `id` | Key ID |
| `project_id` | 项目 ID |
| `organization_id` | 组织 ID，项目级 Key 为空 |
| `scope` | 项目 Key 固定为 `PROJECT` |
| `note` | Key 备注 |
| `public_key` | Public Key |
| `hashed_secret_key` | Secret Key 哈希 |
| `fast_hashed_secret_key` | 快速校验哈希 |
| `display_secret_key` | 脱敏展示 Secret |
| `last_used_at` | 最近使用时间 |
| `expires_at` | 过期时间 |
| `is_in_app_agent_key` | 是否应用内 Agent Key |
| `created_at` | 创建时间 |

项目设置页 API Keys 仅展示 `scope = PROJECT` 且 `is_in_app_agent_key = false` 的 Key。

## 5. 角色与权限规则

### 5.1 项目角色定义

| 角色 | 可见名称 | 权限定位 |
| --- | --- | --- |
| `OWNER` | 项目 owner | 可管理所有项目设置和成员权限 |
| `ADMIN` | 项目 admin | 可管理项目配置、评分指标、模型、API Keys，可管理低于或等于自身权限的成员 |
| `MEMBER` | 项目 member | 可使用项目业务功能，不可管理项目成员和敏感设置 |
| `VIEWER` | 项目 viewer | 只读访问 |

### 5.2 设置页权限矩阵

| 操作 | Owner | Admin | Member | Viewer |
| --- | --- | --- | --- | --- |
| 查看通用设置 | 是 | 是 | 是 | 是 |
| 编辑通用设置 | 是 | 是 | 否 | 否 |
| 查看评分指标 | 是 | 是 | 是 | 是 |
| 新增/编辑/归档评分指标 | 是 | 是 | 否 | 否 |
| 查看项目成员 | 是 | 是 | 是 | 是 |
| 新增项目成员 | 是 | 是 | 否 | 否 |
| 删除项目成员 | 是 | 是 | 否 | 否 |
| 修改成员权限 | 是 | 是 | 否 | 否 |
| 查看模型设置 | 是 | 是 | 是 | 是 |
| 管理模型设置 | 是 | 是 | 否 | 否 |
| 查看 API Keys | 是 | 是 | 否 | 否 |
| 新增/编辑/删除 API Keys | 是 | 是 | 否 | 否 |

### 5.3 成员授权限制

- 操作者只能授予不高于自身有效项目角色的角色。
- `Admin` 不能授予或修改出 `Owner`。
- 不允许删除项目最后一个 `Owner`。
- 不允许将最后一个项目 `Owner` 降级为非 `Owner`。
- 删除项目成员只删除 `project_memberships`，不删除 `users` 或 `organization_memberships`。
- 用户不在项目所属组织内时，应优先创建 `membership_invitations` 或提示先加入组织，再设置项目角色。
- 项目成员角色变更应记录审计日志。

## 6. 功能需求

### 6.1 项目设置入口与导航

入口：

- 项目卡片“项目设置”按钮。
- 项目详情页侧边栏或顶部菜单中的“设置”入口。

设置页分区：

| 分区 | 路由建议 | 说明 |
| --- | --- | --- |
| 通用设置 | `/projects/{projectId}/settings/general` | 项目基础信息 |
| 评分指标 | `/projects/{projectId}/settings/scores` | Score Configs |
| 项目成员 | `/projects/{projectId}/settings/members` | Project Memberships |
| 模型设置 | `/projects/{projectId}/settings/models` | Models、LLM Connections、Default Model |
| API Keys | `/projects/{projectId}/settings/api-keys` | Project API Keys |

### 6.2 通用设置

展示字段：

| 字段 | 来源 |
| --- | --- |
| 项目 ID | `projects.id` |
| 项目名称 | `projects.name` |
| 项目描述 | `projects.metadata.description` |
| 所属组织 | `projects.org_id` 关联 `organizations.name` |
| 数据保留天数 | `projects.retention_days` |
| 创建时间 | `projects.created_at` |
| 更新时间 | `projects.updated_at` |

编辑规则：

- 支持编辑项目名称和项目描述。
- 项目名称不能为空。
- 项目描述建议限制 500 字以内。
- 项目描述写入 `projects.metadata.description`。
- 编辑后刷新项目管理列表和项目设置页展示。

### 6.3 评分指标

列表字段：

| 字段 | 来源 |
| --- | --- |
| 指标名称 | `score_configs.name` |
| 类型 | `score_configs.data_type` |
| 描述 | `score_configs.description` |
| 数值范围 | `min_value`、`max_value` |
| 分类选项 | `categories` |
| 状态 | `is_archived` |
| 创建时间 | `created_at` |
| 更新时间 | `updated_at` |

新增规则：

- `NUMERIC`：需支持最小值、最大值，可为空；若同时填写，最小值不能大于最大值。
- `CATEGORICAL`：需配置分类选项，选项 label 和 value 不允许重复。
- `BOOLEAN`：选项由 Langfuse 自动推断，不需要自定义 categories。
- `TEXT`：不需要数值范围和分类选项。

编辑规则：

- 支持修改名称、描述、数值范围、分类选项。
- 支持归档和取消归档。
- 归档不删除历史 scores，不影响历史展示。

### 6.4 项目成员

列表字段：

| 字段 | 来源 |
| --- | --- |
| 用户 ID | `users.id` |
| 姓名 | `users.name` |
| 邮箱 | `users.email` |
| 组织角色 | `organization_memberships.role` |
| 项目角色 | `project_memberships.role` |
| 有效角色 | 组织角色与项目角色综合计算 |
| 加入项目时间 | `project_memberships.created_at` |
| 更新时间 | `project_memberships.updated_at` |

新增成员：

1. 用户输入邮箱或搜索组织内用户。
2. 选择项目角色：项目 owner、项目 admin、项目 member、项目 viewer。
3. 后端校验用户是否属于项目所属组织。
4. 若用户已属于组织且没有项目成员关系，创建 `project_memberships`。
5. 若用户已有项目成员关系，返回“用户已是项目成员”。
6. 若用户不属于组织，按产品策略创建 `membership_invitations`，携带 `project_id` 和 `project_role`，或提示先加入组织。

删除成员：

- 删除前必须二次确认。
- 删除 `project_memberships` 记录。
- 不删除组织成员关系。
- 不删除用户账号。
- 若被删除成员是最后一个项目 `Owner`，禁止删除。

修改成员权限：

- 支持在 `OWNER`、`ADMIN`、`MEMBER`、`VIEWER` 间调整。
- 不展示 `NONE` 作为可选角色。
- 操作者不能授予高于自身有效角色的权限。
- 若将最后一个 `Owner` 调整为其他角色，禁止操作。
- 修改成功后刷新成员列表。

### 6.5 模型设置

模型设置分为三类：

| 子分区 | 数据模型 | 说明 |
| --- | --- | --- |
| 模型定义 | `models`、`prices`、`pricing_tiers` | 用于 trace 成本计算和模型匹配 |
| LLM 连接 | `llm_api_keys` | 用于评估器、playground 等调用外部模型 |
| 默认评估模型 | `default_llm_models` | 用于没有显式模型配置的评估器 |

模型定义列表字段：

| 字段 | 来源 |
| --- | --- |
| 模型名称 | `models.model_name` |
| 匹配规则 | `models.match_pattern` |
| 生效日期 | `models.start_date` |
| 计价单位 | `models.unit` |
| 输入价格 | `input_price` 或默认 pricing tier |
| 输出价格 | `output_price` 或默认 pricing tier |
| 总价 | `total_price` 或默认 pricing tier |
| 是否 Langfuse 内置 | `project_id is null` |

LLM 连接列表字段：

| 字段 | 来源 |
| --- | --- |
| Provider | `llm_api_keys.provider` |
| Adapter | `llm_api_keys.adapter` |
| Base URL | `llm_api_keys.base_url` |
| Secret Key | `display_secret_key` |
| Custom Models | `custom_models` |
| With Default Models | `with_default_models` |
| 更新时间 | `updated_at` |

默认评估模型规则：

- 每个项目最多一个 `default_llm_models` 记录。
- 默认模型必须引用当前项目有效的 `llm_api_keys`。
- 删除被默认模型使用的 LLM 连接时，应同步清理默认模型或阻塞相关 evaluator 配置，参考 Langfuse 机制。

### 6.6 API Keys

列表字段：

| 字段 | 来源 |
| --- | --- |
| Key ID | `api_keys.id` |
| Public Key | `api_keys.public_key` |
| Secret Key | `display_secret_key` |
| 备注 | `note` |
| 最近使用时间 | `last_used_at` |
| 过期时间 | `expires_at` |
| 创建时间 | `created_at` |

新增规则：

- 用户输入备注，可为空。
- 后端调用 Langfuse 项目 API Key 创建能力生成 PK/SK。
- 创建成功时返回完整 secret key，仅允许前端展示一次。
- 后续查询仅展示 `display_secret_key`。

编辑备注：

- 支持修改 `note`。
- 备注需进行 HTML 清理或使用 StringNoHTML 校验。

删除规则：

- 删除前必须二次确认。
- 删除后该 Key 不能再访问项目 API。
- 不允许删除 `is_in_app_agent_key = true` 的 Key。

## 7. API 设计

Plus 层对外响应统一遵循：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "txId": "trace-id"
}
```

分页列表响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 0,
    "datas": []
  },
  "txId": "trace-id"
}
```

### 7.1 查询项目通用设置

`GET /projects/{projectId}/settings/general`

响应 data：

```json
{
  "id": "project_xxx",
  "name": "评测项目",
  "description": "用于 Agent 评测",
  "orgId": "org_xxx",
  "orgName": "默认组织",
  "retentionDays": null,
  "createdAt": "2026-07-03T10:00:00.000Z",
  "updatedAt": "2026-07-03T10:00:00.000Z"
}
```

### 7.2 更新项目通用设置

`PATCH /projects/{projectId}/settings/general`

请求体：

```json
{
  "name": "评测项目",
  "description": "用于 Agent 评测"
}
```

### 7.3 查询评分指标

`GET /projects/{projectId}/settings/score-configs?page=1&pageSize=20`

实现要求：

- 优先调用或复用 Langfuse Score Configs 查询能力。
- 返回字段与 Langfuse score config API 保持一致。

## 8. 数据流

### 8.1 项目设置页加载

1. 前端进入项目设置页。
2. Plus 层校验当前用户是否具备项目访问权限。
3. 查询项目基础信息和当前用户有效项目角色。
4. 根据权限返回可见分区和可操作按钮。
5. 前端按分区懒加载评分指标、成员、模型和 API Keys。

### 8.2 新增项目成员

1. 用户输入邮箱并选择项目角色。
2. Plus 层校验操作者是否具备项目成员管理权限。
3. Plus 层校验授予角色不高于操作者有效角色。
4. 查询用户是否属于项目所属组织。
5. 已属于组织时创建 `project_memberships`。
6. 未属于组织时创建 `membership_invitations` 或提示先加入组织。
7. 记录审计日志并返回成员信息。

### 8.3 修改成员权限

1. 用户选择目标角色。
2. Plus 层校验操作者权限和角色层级。
3. 校验不会移除最后一个项目 `Owner`。
4. 更新 `project_memberships.role`。
5. 记录审计日志并刷新列表。

### 8.4 API Key 创建

1. 用户输入 Key 备注。
2. Plus 层校验 `apiKeys:CUD` 权限。
3. 调用 Langfuse Key 创建能力生成并存储哈希 secret。
4. 创建成功响应返回完整 secret。
5. 前端提示用户完整 secret 仅展示一次。

## 9. 安全与审计

- API Key、LLM Secret Key、extra headers 不允许写入日志。
- 项目 API Key 查询只返回脱敏 secret。
- LLM 连接查询不返回明文 secret 和明文 extra headers。
- 成员管理、API Key 管理、评分指标变更、模型设置变更必须记录审计日志。
- 外部输入必须使用 Pydantic schema 或等价 schema 校验。
- SQL 必须使用 SQLAlchemy 参数绑定。
- 内部 API 必须校验当前用户项目权限，不能只依赖前端隐藏按钮。
- 操作者不得授予高于自身有效项目角色的权限。

## 10. 异常处理

| 场景 | 处理 |
| --- | --- |
| 无项目访问权限 | 返回无权限错误 |
| 无设置管理权限 | 返回无权限错误 |
| 项目不存在或已归档 | 返回资源不存在或项目不可用 |
| 项目名称为空 | 返回参数错误 |
| 评分指标名称重复或不合法 | 返回业务错误 |
| 数值指标范围非法 | 返回参数错误 |
| 分类指标选项重复 | 返回参数错误 |
| 新增成员邮箱不存在 | 创建邀请或提示先加入组织 |
| 用户已是项目成员 | 返回业务错误 |
| 删除最后一个项目 owner | 返回业务错误 |
| 修改最后一个项目 owner 为其他角色 | 返回业务错误 |
| 授予角色高于操作者角色 | 返回无权限错误 |
| API Key 不存在 | 返回资源不存在 |
| LLM 连接 secretKey 为空 | 返回参数错误 |
| 缺少加密环境变量 | 返回内部配置错误，不暴露敏感细节 |

## 11. 验收标准

- `docs/prd/` 目录中存在本需求文档。
- 项目设置页包含通用设置、评分指标、项目成员、模型设置、API Keys 五个分区。
- 通用设置可查看项目基础信息，并可按权限编辑项目名称和描述。
- 评分指标复用 Langfuse `score_configs`，支持查询、新增、编辑、归档。
- 项目成员复用 Langfuse `project_memberships`，支持新增、删除、修改权限。
- 项目成员角色支持项目 owner、项目 admin、项目 member、项目 viewer。
- 成员管理不允许删除或降级最后一个项目 owner。
- 模型设置复用 Langfuse `models`、`llm_api_keys`、`default_llm_models`。
- API Keys 复用 Langfuse `api_keys`，scope 为 `PROJECT`。
- API Key 和 LLM Secret Key 不在列表接口返回明文。
- 不修改 `langfuse/` 目录源码。
- 不修改 Langfuse 原生表结构。
